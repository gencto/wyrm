- 0.2.22 (2026-11-09): 06 — a key from a port inside a scope: `subscribe` and `liveliness` get the input `in.key`, the output `error` and the parameter `key_scope` (a key expression inside this site's `downstream`, `dataflows` or `storage`; required when `in.key` is wired, validation step 4a; no default). The deployer's `auth` reads all of the scope (a grant below `read` that touches it refuses, a read grant on a part leaves the rest to later grants); `watch`, `ports` and `preview` ask the same of their caller. At run time a value is taken only as one concrete node key (text, ≤ 512 bytes, segments `[A-Za-z0-9_.-]+`) inside the scope; a new key ends the old read first (`out` `null`/`uncertain` until its first sample), a refused value reads nothing and gives a text on `error`, `null` reads nothing; changes ≥ 100 ms apart, the latest wins. - 0.2.23 (2026-11-09): 06 — the action block: `invoke.args` keys are fields with ports `arg.<name>` (constant, then the last sample; ≤ 64); `invoke` and `set` get `interval_ms` (0 or 100 … 86 400 000; first run one full period after the start), `auto_run` (`invoke` false: a changed argument runs it; `set` true: today's write on `in`), `enabled`, the input `trigger` (an event, or a value that differs from the last one) and the outputs `sent`, `ok`, `error` (`{event, id, code, message}`), `running`, `last_run`, `invoke` also `result` (`out` kept). A sample born at the start (a variable's or `const`'s start value, a parameter echo's start value, a clock's first tick, the first sample of a read, and what a node sends while it handles one) never runs a command through `trigger` or `auto_run`. `dataflows/<id>/~act/trigger {node}` (level `write`; the caller's `auth` holds `max(maxperm, write)` on the block's target, as the deployer's proof; a running flow only). `run_on_start` (bool, default false, no port; owner decision 2026-11-09: one action block whose fields set its behaviour, no block type per behaviour): true runs the block exactly once at each start of the flow, 250 ms after the node started, the one sanctioned exception to the start rule. In a preview the command blocks report `sent` and never an answer. `node_types` adds `dyn_inputs.keys` and `trigger` (ADR 0040 §2). No fixture change.

- 0.2.30 (2026-11-11): 06 — what calculates at start: a pure logic block (math, trigonometry, statistics, `not`, `if`, `case`, `select`, text, codecs, `make_object`, `make_array`, `get`, `stats`, the date blocks but `now`, the table blocks but `table_page` and `table_recorder`; 83 types) with no edge into any of its ports calculates once at start from its constants and parameters; a block with a wired input waits for its first sample as before. The `liveliness` catalog entry gets its own `key` description (a node whose presence is read). No fixture change (no wire format change).
