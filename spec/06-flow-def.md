# 06 — `dataflows/<id>/~def`

CBOR map (на дроті) / JSON (у конфігах і UI) — одна схема. Рядкові ключі (користувацький вміст).

```
{
  "id": tstr,                 // = сегмент ключа
  "version": uint,            // монотонно; engine ігнорує ≤ поточної
  "enabled": bool,            // default true
  "description": tstr?,
  "nodes": { <node_id>: { "type": tstr, ...config, "placement": "local"|"process"|"wasm"? } },
  "edges": [ [ "<node>.<port>", "<node>.<port>" ] ],
  "policy": { "overflow": "drop_oldest"|"drop_newest"|"block", "queue": uint, "state_flush_s": uint, "restart": {"backoff_max_s": uint} },
  "permissions": { "token": tstr, "maxperm": uint },
  "layout": { <node_id>: [ x, y ] },  // 0.2.5: де редактор малює ноду; компілятор не зважає
  "blocks": { <name>: { "description": tstr?, "inputs": [ {"name": tstr, "to": tstr | [tstr], "default": any?, "description": tstr?} ],
                        "outputs": [ {"name": tstr, "from": tstr, "description": tstr?} ],
                        "nodes": {…}, "edges": […], "layout": {…}? } }   // 0.2.24: власні блоки
}
```
Порти: `<node>.out`, `<node>.in`, іменовані `<node>.in.<name>` / `<node>.out.<name>` (у `expression` — `in.<input>`; у `alarm` — `out`, `event`).

Поля як виходи (0.2.15, ADR 0038): кожне поле ноди є також виходом, з якого може починатися ребро.
- Параметр `p` дає вихід `p` з ефективним значенням: з конфігу або default, а де є порт `in.<p>` — останній семпл на ньому. Вихід надсилає значення один раз на старті і далі на кожну зміну.
- Вхід `x`, що не є портом параметра (`in`, `reset`, `in.0`, …), дає вихід `x`. Він повторює кожен семпл на `x` до того, як нода його обробить.
- Назва виходу така сама, як у поля: `scale1.input_min`, `if1.in.0` (ребро ділиться на першій крапці: нода `if1`, порт `in.0`).
- Конфлікт назв: оголошений вихід ноди лишає свою назву; ехо входу йде перед ехо параметра. Тому параметр `reset` у `latch` (є вхід `reset`) не має виходу (`echo: false` у каталозі).
- Тип виходу: ехо входу — тип входу; ехо параметра — `number`, `bool`, `map` за типом параметра, інші (`string`, `dynamic`, `array`) — `any`. Крок 4 валідації перевіряє ці типи, як і решту.
- Ехо-вихід, з якого не йде жодне ребро, не будується: runtime не копіює для нього семпл.

Порти параметрів старших типів нод (0.2.17, ADR 0038 §5a): `scale` — `in.k`, `in.b`; `alarm` — `in.high`, `in.low`, `in.hysteresis`, `in.delay_s`, `in.return_delay_s`; `delay` — `in.ms`; `window` — `in.size_s`; `deadband` — `in.abs`, `in.pct`; `timer` — `in.period_ms`. Усі мають тип `number`. Правило як у логічних блоків: значення з конфігу або default на старті, далі перемагає останній добрий семпл. Семпл, що не є скінченним числом або виходить за межі параметра (`period_ms` ≥ 10, `size_s` > 0, `ms` ≥ 0, `delay_s` і `return_delay_s` ≥ 0), ігнорується. Правила конфігу не змінюються (`high` або `low`, `abs` або `pct` тощо обов'язкові). Новий `period_ms`, `ms`, `size_s` або затримка `alarm` діє одразу: годинник ноди починається заново через один період після зміни.

Текстові оператори, `round.text` і `case` (0.2.21, ADR 0038 §8; повний опис — `docs/flow-blocks.md`): `if.op` має ще `!=` (перший вхід не дорівнює жодному з інших), `contains`, `starts_with`, `ends_with` (перший вхід як текст з будь-яким з інших як текстом). `round` має параметр `min_precision` (порт `in.min_precision`) і вихід `text`: число з `precision` знаками, кінцеві нулі обрізано до `min_precision` знаків (default — `precision`). Новий блок `case`: вхід `in`, параметри `op` (`=`, `!=`, `>`, `<`, `>=`, `<=`, `contains`, `starts_with`, `ends_with`) і `else` (default null), змінні входи `inputs` парами (case, then); вихід `out` — then першої пари, чий case збігається з `in` за `op`, інакше `else`. Порожній текст case нічого не збігає.

Порти решти параметрів блоків (0.2.20): `concat` — `in.strict`; `if` — `in.op` (лише відомий оператор, інший текст ігнорується); `hub` — `in.ignore_null`; `trace` — `in.tracing`, `in.msg`. Тепер кожен параметр логічного блоку має порт, крім `value` змінних (його замінює вхід `in`) і `inputs`.

Константи операндів (0.2.19, ADR 0038 §7): логічний блок має ключ конфігу `values: {<port>: <value>}`, наприклад `{type: "concat", values: {"in.0": "AHU-", "in.1": 2}}`. Ключ — операнд блоку: `in` (якщо блок його має) або `in.<name>` з його `inputs`. Не можна: порт параметра, `reset` у `stopwatch`, змінні (`number`, `string`, `bool` мають `value`). Інакше — помилка компіляції `values.<port>: not an operand input`. Константа — значення входу, доки семпл на цьому вході її не замінить (прив'язка перемагає). З 0.2.30 чистий блок без жодного ребра на вході обчислює один раз на старті зі своїх констант і параметрів (див. «Що обчислюється на старті» нижче). Блок, у якого є хоча б одне вхідне ребро, чекає першого семпла, як і раніше; його константи діють, коли семпл прийде. Deploy, гаряча заміна і перезапуск ніколи не виконують `set` або `invoke` через константу. `watch`, `ports` і `preview` показують константу як значення входу від старту. Каталог: `values: true` у типів, чиї операнди беруть константу. `now` константи не бере (0.2.30): його `in` лише запускає; `values` у конфігу `now`, збережений раніше, engine читає й ігнорує.

Що обчислюється на старті (0.2.30, звужує правило ADR 0032 §5):
1. Змінні (`number`, `string`, `bool`, `table`) і `constant` надсилають значення на старті.
2. Чистий блок без вхідних ребер обчислює один раз на старті зі своїх констант і параметрів. «Без вхідних ребер» означає: жодне ребро не веде в жоден його порт (операнд, порт параметра, `reset`). Чисті блоки — функції лише своїх входів і параметрів, без стану, подій і власного годинника: математика, тригонометрія, статистика, `not`, `if`, `case`, `select`, текст, кодеки, `make_object`, `make_array`, `get`, `stats`, `date_time`, `date_format`, `date_parse`, `date_math`, `date_range` і табличні блоки, крім `table_page` і `table_recorder`. Повний перелік (83 типи) — `docs/flow-blocks.md`.
3. Не чисті (чекають семпла): `counter`, `toggle`, `changed`, `rising_edge`, `falling_edge`, `event_gate`, `sample_and_hold`, `debounce`, `throttle`, `stopwatch`, `hub`, `trace`, `catch_error`, `router`, `table_recorder`, `table_page`, `now`, а також ноди, що не є логічними блоками.
4. `now` дає час на старті, якщо його `interval_ms` більший за 0.
5. Те, що надсилають правила 2 і 4, — семпл «з констант». Він також «народжений на старті», і runtime переносить обидві позначки на все, що нода надсилає, обробляючи такий семпл. Семпл «з констант» не запускає команду ніде: ні через `trigger`, `auto_run`, `arg.<name>`, ні через `in` у `set` та `invoke`. Він лише дає полю значення. Стартове значення змінної — не «з констант»: на `in` команди воно пише, як раніше (УВАГА нижче).

Ключ з порту в межах scope (0.2.22, ADR 0040 §1): `subscribe` і `liveliness` мають вхід `in.key`, вихід `error` і параметр `key_scope`.
- `key` у конфігу — стартовий ключ. Його може не бути, якщо є `key_scope`.
- `key_scope` — key expression (відносний від `wy/<site>/` або повний), наприклад `downstream/modbus/line1/**`. Він обов'язковий, коли в `in.key` входить ребро: інакше помилка компіляції `nodes.<id>.key_scope: required when in.key is wired`. Scope за замовчуванням немає.
- Scope лежить у `downstream`, `dataflows` або `storage` свого сайту (крок 9). Секція є літеральним префіксом scope.
- Deploy: `auth` деплоєра дає `read` на весь scope. Гранти читаються по порядку: грант нижче `read`, що перетинає scope, відмовляє; грант `read`, що покриває весь scope, дозволяє; грант `read` на частину лишає решту наступним грантам. `watch`, `ports` і `preview` перевіряють те саме для того, хто викликає.
- Runtime приймає значення з порту, лише коли воно: текст; не порожнє; не довше 512 байтів; один конкретний ключ вузла (кожен сегмент `[A-Za-z0-9_.-]+`: без `*`, `**`, `$*`, без `~meta`, без порожніх сегментів); у секціях свого сайту; у межах scope.
- Новий ключ: спершу закінчується старе читання, `out` надсилає `null` з якістю `uncertain` і лишається таким до першого семпла нового ключа. Ефективний `key` (ехо-вихід `key`, `params.key` у `watch`) — ключ, як його написано.
- Відмова: нода нічого не читає, `out` — `null`/`uncertain`, ефективний `key` — `null`, вихід `error` несе причину текстом. `error` повертається до `null` з наступним прийнятим ключем.
- `null` на порту: нода нічого не читає, помилки немає.
- Між двома змінами ключа минає щонайменше 100 мс. Значення, що прийшло раніше, чекає; перемагає останнє.
- Цілі команд (`set.path`, `invoke.path`, `invoke.action`) і `publish.node` портів не мають (ADR 0040 §1a).
- Каталог: `params[].scope` — назва параметра, що тримає scope цього поля (`key` → `"key_scope"`).

Блок дії та поведінка команд (0.2.23, ADR 0040 §2): `invoke` і `set` мають поля поведінки, вхід `trigger` і виходи-події.
- Аргументи `invoke`: кожен ключ мапи `args` — аргумент. Значення ключа — константа аргументу. Порт `arg.<name>` замінює її останнім семплом. Не більше 64 аргументів; назва має 1–128 байтів і не починається з `__`. Константа `"$in"` означає останнє значення на `in`.
- `interval_ms` (порт `in.interval_ms`, default 0): 0 — вимкнено; інакше 100 … 86 400 000. Нода запускається кожен період, уперше — через повний період після старту. Період пропускається, доки попередній запуск не отримав відповіді.
- `auto_run` (порт `in.auto_run`): у `invoke` (default false) семпл на `arg.<name>`, що змінює аргумент, запускає дію. У `set` (default true) значення на `in` записується, як раніше; `false` — `in` лише тримає значення.
- `enabled` (порт `in.enabled`, default true): `false` — ноду нічого не запускає.
- `run_on_start` (bool, default false, без порту): `true` — нода запускається рівно один раз на кожен старт флоу (deploy, гаряча заміна, reload, перезапуск), через 250 мс після старту ноди. Це єдиний дозволений виняток з правила старту, і його обирають для кожного блоку окремо. Вимкнена нода стартового запуску не робить. `set` пише значення, яке `in` отримав до цього моменту, і не пише його вдруге після `auto_run`. У preview стартовий запуск — це рядок `sinks`, а не запис.
- Один блок, а не окремий тип на кожну поведінку: поведінку задають поля `trigger`, `auto_run`, `interval_ms`, `enabled`, `run_on_start`. Старий `on` у `invoke` діє лише для `in`, як раніше (`change` відповідає `trigger` зі значенням; `rising`/`falling` — блоку фронту перед `trigger`).
- Вхід `trigger`: подія `{event, id}` запускає ноду; інше значення запускає її, коли воно відрізняється від попереднього семпла на `trigger`. `null` і семпл якості `bad` (без `allow_bad`) нічого не запускають.
- `in` працює, як раніше: `invoke` запускається на кожен семпл, що проходить `on`; `set` бере значення для запису.
- Виходи обох типів: `sent` (подія: запит пішов), `ok` (подія: ціль відповіла без помилки), `error` (подія `{event, id, code, message}`: `code` — код статусу spec 04), `running` (bool), `last_run` (час останнього `sent`, мкс). `invoke` має ще `result` (останній результат) і `out` (результат з якістю `good` або текст помилки з якістю `bad`, як раніше).
- Правило старту: семпл «народжений на старті» ніколи не запускає команду через `trigger` або `auto_run`. Такими є: стартове значення змінної та `const`, стартове значення ехо параметра, тік годинника на старті, перший семпл читання (`subscribe`, `liveliness`), а також усе, що нода надсилає, обробляючи такий семпл. Тому deploy, гаряча заміна, reload і перезапуск не виконують команду через `trigger`, `auto_run` чи `interval_ms`. `in` цього правила не має (див. УВАГА нижче), крім семпла «з констант» (0.2.30): він на `in` лише дає значення.
- `dataflows/<id>/~act/trigger {node}` — рівень `write`; один запуск ноди `invoke` або `set` задеплоєного флоу, що працює. `auth` того, хто викликає, дає на ціль ноди (`…/~act/<a>` або `…/~set`) рівень `max(maxperm, write)` — той самий, що deploy вимагає від proof деплоєра; інакше `permission_denied`. Інша нода — `invalid_parameter`; флоу не працює — `not_supported`.
- У preview `set` та `invoke` не мають клієнта: вони повідомляють у `sinks`, що надіслали б, дають `sent` і `last_run`, і ніколи не дають `ok`, `error`, `result`, `out`, `running`.
- Каталог: `dyn_inputs.keys: true` — параметр є мапою, порти названі її ключами (`invoke.args` → `arg.<name>`); `trigger: true` у типів, які запускає `~act/trigger`.

УВАГА: ехо параметра надсилає значення на старті. Ребро з нього до `invoke` або `set` виконує команду при deploy. Так само діє стартове значення змінної і перший семпл `subscribe` на `in` команди. Чистий блок без вхідних ребер команди не виконує (0.2.30).

`layout` належить редактору (ADR 0019). Ключ — це `node_id` або ключ редактора `<node>~<name>~<rest>` (0.2.26; `~` не може бути в `node_id`, тому такий ключ не сплутати з нодою). Редактор Studio зберігає так вибір пінів блоку: `"<node>~pin~<field>": [1|0, 0]`. Значення кожного ключа — два скінченні числа. Engine ключі редактора не читає і не вимагає, щоб нода ключа існувала; він зберігає `layout` як надіслано. Ліміти: не більше 16 384 записів, ключ не довший за 256 байтів (інакше помилка компіляції `layout: …`). Те саме правило діє для `layout` власного блоку. Він не входить до конфігу ноди, тож переміщення ноди не скидає її стан при гарячій заміні.

Каталог типів нод для редактора: `dataflows/~act/node_types` (рівень `read`) повертає масив `{type, category, description, inputs, outputs, dyn_inputs?, dyn_outputs?, port_types, echo_inputs?, values? (0.2.19), params: [{name, type, required, description, choices?, default?, editor?, port?, scope? (0.2.22), echo, display? (0.2.29)}]}`; `dyn_inputs`/`dyn_outputs` = `{param, prefix, default}` — порти, які дає параметр (`expression`: `in.<name>` з `inputs`; `wasm`: `inputs`/`outputs`).

Поля 0.2.15 (ADR 0038, лише додані):
- `params[].default` — типізоване значення для кожного параметра, що його має: число лишається числом, `choices` — рядком, список імен — масивом (`inputs` блоків: `["0", "1"]`). Без default поля немає.
- `params[].port` — `"in.<p>"`, коли в параметра є вхідний порт; інакше поля немає.
- `params[].echo` — `true`, коли параметр має вихід своєї назви; `false` при конфлікті назв (див. «Поля як виходи»).
- `port_types` — `{<port>: <type>}` (`number`, `bool`, `map`, `any`) для фіксованих входів і виходів, для динамічних портів з їхніми `default` і для ехо-виходів. Динамічні порти з іншими назвами мають тип `any`.
- `echo_inputs: true` — входи типу, що не є портами параметрів, повторюються як виходи. У типів без входів поля немає.

## Другий набір блоків (0.2.25, ADR 0040 §4; повний опис — `docs/flow-blocks.md`)
- Читачі: `load_value` (одне читання збереженого значення точки; `key`, порт `in.key`, scope `key_scope`) і `list_children` (діти вузла як список рядків `{name, path, type?, display?, is?, unit?, writable, has_children}`, не більше 1000; `path`, порт `in.path`, scope `path_scope`). Обидва мають `interval_ms`, `auto_run` (default true: читання на старті і при зміні ключа), `enabled`, вхід `trigger` і виходи `out`, `ok`, `error` (`{event, id, code, message}`), `running`, `last_run`. Їхній ключ і scope перевіряються як джерело (крок 9, права deploy і `watch`). Читання — не команда: правило старту для `auto_run` читача не діє. `list_children` показує рядок кожної дитини, тому deploy, `watch`, `ports` і `preview` вимагають читання також `<path>/*` і `<path_scope>/*`: одна заборонена дитина відмовляє.
- Текст: `substring` (`start`, `length`), `replace` (`from`, `to`), `split` (`separator`; не більше 1000 частин), `join` (`separator`). Результат довший за 4 КіБ — `null` з якістю `bad`.
- Дані: `make_object` (мапа іменованих входів), `make_array`, `get` (`path` виду `a.b.0`), `stats` (виходи `min`, `max`, `avg`, `sum`, `count` для чисел списку).
- Події і стан: `changed` (вихід `on_change`), `rising_edge`, `falling_edge` (вихід `on_edge`), `counter` (`step`, `initial`, вхід `reset`), `toggle` (`initial`, `reset`), `sample_and_hold` (входи `in`, `trigger`), `select` (`index`). Семпл, народжений на старті, дає блоку значення і нічого не запускає.
- Час: `debounce` і `throttle` (`ms`, не більше 3 600 000).
- Кожен параметр цих блоків має порт `in.<p>`, крім `inputs` і scope.
- Число з порту або з конфігу, що не є скінченним (NaN, ±inf), блок числом не вважає; такий семпл на порту параметра ігнорується, і діє останнє добре значення. `ms` без числа — 500; `substring.length` — не більше 4 КіБ; `select.index` поза входами дає `null`.

## Третій набір блоків (0.2.29, ADR 0044; повний опис — `docs/flow-blocks.md`)
- Математика: `constant` (`name`: `pi`, `e`, `sqrt2`, `ln2`, `ln10`, `log2e`, `log10e`; надсилає на старті, як змінна), `factorial`, `log` (`base`), `power` (`exponent`), `root` (`degree`), `bound` (`min`, `max`; виходи `input_out_of_range`, `out`), `round_up`, `round_down` (`precision`; виходи `out`, `text`), `format_number` (`format`, `decimal_separator`, `group_separator`), `parse_number`.
- Тригонометрія в градусах: `sin`, `cos`, `tan`, `cot`, `asin`, `acos`, `atan` (`x`, default 1), `to_degrees`, `to_radians`.
- Статистика за змінними входами: `average`, `median`, `mode`, `std_deviation`, `variance`; вхід зі списком дає його числа (не більше 1000).
- Текст і кодеки: `left`, `right` (`length`), `trim`, `base64_encode`, `base64_decode` (виходи `out`, `bytes`), `url_encode`, `url_decode`, `to_camel_case`, `from_camel_case`, `hash` (`algorithm`: `sha256`, `sha1`, `md5`), `json_parse` (виходи `out`, `parse_error`; не більше 256 КіБ і 32 рівнів), `json_stringify` (`pretty`).
- Старі блоки (конфіг без нового поля дає те саме, що раніше): `substring` бере `end` (без `length`; від'ємний рахує з кінця), `replace` бере `regexp` (`from` — шаблон), `case` має оператор `regexp`. Шаблон — не більше 256 байтів і 64 КіБ після компіляції, лінійний час (`regex`), без backreferences; шаблон, що не компілюється, нічого не знаходить.
- Дата і час: дата — це мікросекунди від епохи Unix, як `t` семплу; вхід бере також текст RFC 3339, `yyyy-M-d[ H:mm[:ss[.f]]]`, `yyyy/M/d …`, `M/d/yyyy …` (з `am`/`pm`). `time_zone` — назва IANA, `UTC` (default) або `±HH:MM` (tzdb з `jiff`; час у проміжку DST — вперед, повторений — раніший). Блоки: `now` (поточний час: на старті, кожні `interval_ms` і на кожен семпл `in`; з 0.2.30 параметр `interval_ms` з портом, default 1000, 0 — лише на семпл `in`, інакше 100 … 86 400 000; стартове значення — «з констант», наступні тіки — звичайні семпли; `in` лише запускає і константи не бере), `date_time` (`year`…`millisecond`, `time_zone`), `date_format` (`format`, `time_zone`, також `auto`), `date_parse` (виходи `time`, `year`, `month`, `day`, `hour`, `minute`, `second`, `millisecond`, `weekday`: 1 — понеділок), `date_math` (`op`: `after`/`before`; роки, місяці й дні — за календарем зони, решта — як пройдений час), `date_range` (входи `in`, `next`, `previous`; `format`, `range_delimiter`, `keep_special`, `week_start` (default `monday`), `time_zone`; виходи `start`, `end` (включно), `this_range`, `next_range`, `previous_range`, `formatted`, `duration`). `previousN<unit>` — період перед `currentN<unit>`. Іменований або відносний діапазон рахується знову щосекунди.
- Логіка і події: `router` (входи `in`, `condition` і змінні входи — значення випадків; виходи `out.<name>` для кожного випадку і `else`; `op` як у `case`, `single_output`), `event_gate` (вхід `reset`, змінні входи; `log_order`: `none`, `first_occurrence`, `last_occurrence`, `all`; виходи `on_finish`, `order`), `catch_error` (змінні входи — події `error` або тексти; виходи `out`, `code`, `source`, `on_error`). Семпл, народжений на старті, не рахується.
- Читачі: `load_history` (`key`, `in.key`, `key_scope`; `time_range` — текст діапазону, як у `date_range`, default `today`; `rollup`, `window`, `limit` ≤ 10 000, `time_zone`; `out` — таблиця `{t, v, q}`; подія `ok` має `rows` і `truncated`, коли відповідь досягла `limit`) і `get_node` (виходи `out` — підсумок вузла, `actions` — таблиця дій з їхніми параметрами). Обидва перевіряються як джерело (право читання ключа і всього `key_scope`). Кожен читач (також `load_value`, `list_children`) запускає `dataflows/<id>/~act/trigger {node}`; тоді той, хто викликає, має право читання ключа і всього scope читача (для `list_children` — і дітей), а не рівень команди; крім того, для кожної ноди `set` чи `invoke` нижче за течією від ноди, яку запускають (через усі ребра, транзитивно, з розгорнутими власними блоками), той, хто викликає, має рівень `max(maxperm, write)` на її ціль — так само й для ноди-команди, відповідь якої запускає іншу команду; каталог дає читачам `trigger: true`.
- Таблиця (значення): `{columns: [<name>…], rows: [{<name>: <cell>…}…]}`; вхід бере також список мап і рядки-списки за позицією. Не більше 10 000 рядків, 128 колонок, назва ≤ 256 байтів, ≤ 512 КіБ клітинок; більша — `null` з якістю `bad`.
- Таблиці: `table` (змінна), `table_recorder` (рядок `{t, <вхід>…}` на кожен семпл змінного входу; `buffer_size` ≤ 10 000, `time_window_s`, `ignore_null`, вхід `reset`), `table_from_csv`, `table_to_csv`, `table_from_json` (`selector`), `table_to_json`, `table_map_columns` (`mapping: [{name, from}]`), `table_sort` (`column`, `method`: `number`/`string`/`natural`, `order`), `table_filter`, `table_remove_rows`, `table_edit_rows` (`expr`, `cells`), `table_group_by` (`column`, `aggregates: [{column, method, as}]`), `table_join` (входи `in`, `right`; `column`, `right_column`, `join`: `left`/`inner`/`right`/`full`/`exclude`/`union`), `table_page` (входи `next`, `previous`, `first`, `last`), `table_rollup` (`time_column`, `interval` `<n>s|m|h|d|w|M|y`, `round_time`, `method`, `aggregates`, `week_start`, `time_zone`), `table_aggregate`, `table_select_rows`, `table_select_columns`, `table_columns`, `table_row_cells`, `table_add_row`, `table_transpose`, `table_from_map`. Скрипти рядків — rhai над `row` і `index`, перевіряються при компіляції (крок 6), разом не довше 100 мс на таблицю.
- Результат, що не є скінченним числом, — `null`.
- Каталог: `params[].display` — підпис поля для редактора, коли підпис з назви був би хибним (лише додано).

## Власні блоки (0.2.24, ADR 0040 §3)
Визначення може мати `blocks`. Нода типу `block:<name>` — екземпляр блоку `<name>`.
- `inputs` і `outputs` блоку — списки (редактор малює поля в цьому порядку). Назва — `[A-Za-z0-9_]+`, унікальна серед входів і виходів разом. Не більше 64 входів і 64 виходів. `to` — один внутрішній вхід `"<inner>.<port>"` або список з 1–16 таких; `from` — внутрішній вихід.
- Параметр блоку — це вхід з `default`. Окремого списку параметрів немає.
- Екземпляр має лише ключ `values: {<input>: <value>}`. Його порти — входи й виходи блоку: `["x.out", "m1.a"]`, `["m1.out", "y.in"]`. Вхід є також виходом своєї назви (ехо першого внутрішнього входу з `to`).
- Компілятор замінює екземпляр внутрішніми нодами з id `<instance>/<inner>` (у вкладеному блоці — `<instance>/<inner instance>/<inner>`). Авторський id не містить `/`.
- Константа входу (`values` екземпляра, інакше `default`) стає константою кожного внутрішнього входу з `to`: порт параметра → конфіг параметра; операнд логічного блоку → його `values`; `arg.<name>` у `invoke` → `args`; `in` змінної → `value`; вхід внутрішнього екземпляра → його `values`. Вхід, що не тримає константи (`filter.in`, `set.in`), дає помилку `nodes.<id>.values.<input>: <inner>.<port> takes no constant`.
- Блок може містити екземпляри інших блоків того самого визначення. Глибина — не більше 4. Блок, що містить себе (прямо або через інші блоки), відхиляється до розгортання: `blocks.<name>: a custom block may not contain itself (a → b → a)`.
- Ліміти розгортання (компілятор рахує їх під час розгортання і зупиняється на першому перевищенні): 1000 нод флоу рахують кожну розгорнуту ноду і кожен екземпляр на кожній глибині; не більше 4000 ребер у флоу після розгортання; один блок має не більше 64 екземплярів інших блоків, 1000 нод і 4000 ребер; не більше 64 блоків у визначенні.
- `publish` усередині блоку має одну назву в кожному екземплярі, тому такий блок можна вжити один раз (крок 7a).
- `watch`, `ports` і `preview` показують внутрішні ноди під їхніми id: `nodes: {"m1/sum": {…}}`. Аргумент `nodes` приймає id екземпляра і тоді означає всі його внутрішні ноди. Окремого рядка екземпляр не має. `~act/trigger` приймає внутрішній id.
- `~def` та історія зберігають визначення, як його надіслано, разом з `blocks`.

Бібліотека блоків сайту (дії на `dataflows`):
- `put_block {name, def}` — рівень `config`; `def` — один блок. Engine перевіряє його, як deploy: сам у пробному флоу, з блоками бібліотеки, які він вживає. Відповідь `{name, version}`; кожен `put` — наступна версія. Не більше 256 блоків, 256 КіБ на блок.
- `get_block {name}` — рівень `read`; відповідь `{name, version, def, requires: {<name>: def}}` з усіма блоками бібліотеки, які він вживає.
- `list_blocks` — рівень `read`; `[{name, version, description?, inputs: [назви], outputs: [назви]}]`.
- `remove_block {name}` — рівень `config`; `not_found`, якщо блоку немає.
- Флоу копіює блок, а не посилається на нього: редактор бере блок через `get_block` і записує його (та `requires`) у `blocks` визначення. Engine під час компіляції бібліотеку не читає.

## Валідація (порядок, перша помилка зупиняє)
1. схема; 2. унікальність `node_id`, `[A-Za-z0-9_]+`; 3. тип ноди є в реєстрі, конфіг за схемою типу; 4. ребра → існуючі порти, сумісні типи; 5. ациклічність (цикл дозволений лише через `delay`); 6. rhai компілюється; 7. `permissions.maxperm` ≥ мін. рівня всіх `invoke/set`-нод і ≤ `write` (флоу не робить config-операцій); 8. ліміти пам'яті (`window.max_samples` сума; з 0.2.24 — не більше 4000 ребер у флоу з розгорнутими власними блоками; з 0.2.16 — не більше 1000 нод у флоу: кожна нода — це задача і черга під час роботи, у задеплоєному флоу і в preview); 9. (0.2.13) `key` кожної ноди `subscribe` і `liveliness` лежить під `wy/<site>/downstream`, `wy/<site>/dataflows` або `wy/<site>/storage` свого сайту (відносний ключ читається від `wy/<site>/`): не `sys`, `pub`, `upstream`, не інший сайт. Engine читає через сесію broker'а, якої ACL не бачить, тому правило перевіряє deploy, validate і старт збереженого флоу. З 0.2.22 те саме правило діє для `key_scope`, а крок 4 має додаток 4a: ребро в `in.key` потребує `key_scope` у конфігу ноди.

Помилка → `dataflows/<id>/~val = {state: 2 (error), error: "<path>: <msg>"}`; стара версія працює.

## `~val` флоу
`{0: {"state": 0 running | 1 stopped | 2 error, "error": tstr?, "version": uint, "since": uint, "deployed_by": tstr?}, 1: q, 2: t}`

`deployed_by` — суб'єкт, що задеплоїв поточну версію (`origin` запиту або `sub` токена). Флоу працює далі, навіть якщо деплоєр втратив права (ADR 0008); поле дає оператору знайти такі флоу.

### Метрики (0.2.31, ADR 0045)
Мапа `~val` має також ключ `stats` (додатковий: старий читач його пропускає):

```
"stats": {"nodes": uint, "edges": uint, "samples_in": uint, "samples_out": uint, "dropped": uint,
          "restarts": uint, "commands": {"sent": uint, "ok": uint, "error": uint}, "last_sample_t": uint?}
```

- `nodes`, `edges` — ноди і ребра скомпільованого флоу (власні блоки розгорнуто).
- `samples_in` — семпли, які ноди взяли зі своїх черг: кожен семпл із ребра і кожен семпл, який отримало власне джерело ноди (`subscribe`, `liveliness`, `const`, позначка «власник зник» у `subscribe`). Внутрішні повідомлення не є семплами: відповідь команди чи читача, запит читача на читання, `~act/trigger`.
- `samples_out` — семпли, які ноди надіслали на вихід, з якого йде хоча б одне ребро (один раз, скільки б ребер не було). Запис `publish`, `set` і `invoke` сюди не входить.
- `dropped` — семпли, які черги нод відкинули за `policy.overflow` (зокрема джерело, що пише в повну чергу при `block`). Семпл, який `publish` пропускає, поки його writer зайнятий, сюди не входить.
- `restarts` — перезапуски після panic ноди.
- `commands` — події `sent`, `ok` і `error` нод `invoke` і `set` (0.2.23). `error` рахує також запуск, відмовлений до надсилання (`busy`), тому `ok + error` може бути більше за `sent`.
- `last_sample_t` — час (µs), коли нода востаннє взяла семпл (як у `samples_in`); немає до першого.

Скидання: лічильники належать поточному запуску. Нові лічильники (усі 0) — при кожному deploy (також hot swap і кожен збережений флоу, який engine деплоїть на своєму старті, тобто при кожному старті broker'а і кожному rebuild ACL), при `start` і при `reload`. Перезапуск після panic лічильники зберігає (`restarts` + 1). Зупинений флоу і флоу в `error` зберігають останні значення. Deploy, що не компілюється, лічильників не змінює.

Публікація: зміна стану (deploy, `start`, `stop`, `reload`, помилка, перезапуск) публікує `~val` одразу, як раніше, з лічильниками цього моменту. Між змінами стану engine публікує `~val` флоу знову не частіше за один раз на період і лише тоді, коли лічильники відрізняються від тих, що були в останньому `~val`. Флоу без руху і зупинений флоу нічого не публікують. Період у `wyrmd` — `metrics_interval_ms` (default 10 с), не менше 5 с.

## Живі значення (0.2.15, ADR 0038)
`dataflows/<id>/~act/watch` — рівень `read`, `stream: true`, `timeout_ms: 30000`. Аргументи: `nodes` (масив id нод; немає або порожній — усі; невідомий id — `invalid_parameter`), `max_hz` (число > 0 і ≤ 20, default 4).

Права: `auth` у `ptok` того, хто викликає (spec 04), має покривати читання кожного джерела флоу (`subscribe`, `liveliness`), як при deploy, і кожної цілі команд (вузол кожної ноди `invoke` і `set`, без `~act/<a>` чи `~set`). Вихід `invoke` несе відповідь цілі, а вхід `set` — те, що нода туди пише. Інакше — `permission_denied`. Помилка engine називає перший ключ, але SDK надсилає цей статус без тексту. Флоу без джерел і без цілей не потребує `auth`.

Рядки (CBOR map, текстові ключі; `[v, q]` — значення і код якості, як у `~val`):
1. перший: `{t, snapshot: true, nodes: {<node>: {in: {<port>: [v, q]}, out: {<port>: [v, q]}, params: {<p>: v}}}}` — кожна нода (або з `nodes`), усі три мапи завжди є; `params` — ефективне значення кожного параметра, що його має;
2. далі: `{t, snapshot: false, nodes: {…}}` — лише ноди і порти, що змінилися після попереднього рядка; порожні `in`/`out`/`params` пропущено. Не більше `max_hz` рядків на секунду; у межах періоду перемагає останнє значення;
3. heartbeat `{t, nodes: {}}` (без `snapshot`), коли 10 с не було рядка;
4. потік закінчується через 30 хв (ttl), при redeploy (останній рядок `{t, redeployed: <version>}`), при remove і при зупинці engine (без рядка). Редактор відкриває його знову.

Engine зберігає останній семпл кожного входу і виходу задеплоєного флоу від старту, навіть без відкритого `watch` (0.2.18). Один слот на порт; новий семпл перезаписує його. Тому змінна, що надіслала значення один раз на старті, є в кожному пізнішому snapshot і в `ports`. Порт без жодного семпла від старту відсутній у `in`/`out`.

Ліміти: ≤ 8 `watch` на флоу, ≤ 64 на сайт. Engine не бачить, що той, хто викликає, пішов: на ліміті новий `watch` того самого суб'єкта (`origin` або `sub`) закриває його найстаріший `watch` (на флоу, а на ліміті сайту — будь-який його); `watch` іншого суб'єкта отримує `busy`.

`dataflows/<id>/~act/ports` — рівень `read`, аргумент `nodes`, ті самі права; повертає рядок 1 (для інструментів без потоку: `wyrm-agent`, MCP) з усіма значеннями портів від старту флоу.

Значення ніколи не пишуться в лог вище `trace`.

## Preview чернетки (0.2.16, ADR 0038 §5)
`dataflows/~act/preview` (на корені `dataflows`) — рівень `read`, `stream: true`, `timeout_ms: 30000`. Аргументи: `def` (визначення в тій самій формі, що й для `deploy`), `nodes` (масив id нод, як у `watch`), `max_hz` (число > 0 і ≤ 20, default 4).

- `def` компілюється, як при deploy і validate (усі кроки валідації). Помилка — `invalid_parameter` з текстом компілятора. `maxperm` і `proofs` не потрібні: preview нічого не пише.
- Права — як у `watch`: `auth` того, хто викликає, покриває читання кожного джерела і кожної цілі команд. Інакше — `permission_denied`.
- Чернетка працює в пісочниці: справжній runtime без збереження (ні `~def`, ні стану нод), без вузла в дереві, з id поза задеплоєними флоу. Чернетка з id задеплоєного флоу не торкається ні цього флоу, ні його `watch`. Читання йде через клієнт без токенів.
- Ноди `set`, `invoke` і `publish` у preview — це ноди-записувачі без клієнта: вони не можуть писати за побудовою. Вони застосовують те саме правило, що й задеплоєна нода (`allow_bad`, `on`, `deadband`, `$in` в `args`), і лише повідомляють результат. `invoke` у preview нічого не надсилає на `out`.
- Рядки — точно як у `watch` (snapshot, зміни ≤ `max_hz`, heartbeat `{t, nodes: {}}` через 10 с). Будь-який рядок може мати ключ `sinks: [{node, op, key, value}]`: `op` — `set`, `invoke` або `publish`; `key` — повний ключ, куди нода писала б (`wy/<site>/<path>/~set`, `wy/<site>/<path>/~act/<action>`, `wy/<site>/dataflows/<def.id>/nodes/<node>`); `value` — значення, а для `invoke` — мапа аргументів після `$in`. Snapshot має останнє від кожної такої ноди; рядок змін — ті, що спрацювали після попереднього рядка, останнє на ноду. Рядок лише з `sinks` — це рядок змін (`snapshot: false`, `nodes: {}`). `nodes` фільтрує і `sinks`.
- Запис іде від старту: перший рядок чекає (≤ 500 мс), доки всі ноди запустяться і стихнуть. Тому snapshot уже має стартові значення змінних і те, що вони дали далі.
- Preview закінчується через 10 хв (ttl), коли новий preview того самого суб'єкта займає його місце, при panic ноди (потік закінчується зі статусом `internal_error`, без перезапуску) і при зупинці engine. Редактор відкриває його знову з останньою чернеткою. Таймери, `stopwatch`, `delay`, `window` працюють як завжди.
- Ліміти: ≤ 2 preview на суб'єкта (`origin` або `sub`; третій закриває найстаріший), ≤ 16 на сайт (`busy` понад це). Engine не бачить, що той, хто викликає, пішов: preview живе до ttl або до заміни.
