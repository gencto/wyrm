# 06 — `dataflows/<id>/~def`

CBOR map (на дроті) / JSON (у конфігах і UI) — одна схема. Рядкові ключі (користувацький вміст).

```
{
  "id": tstr,                 // = сегмент ключа
  "version": uint,            // монотонно; engine ігнорує ≤ поточної
  "enabled": bool,            // default true
  "description": tstr?,
  "nodes": { <node_id>: { "type": tstr, ...config, "placement": "local"|"process"|"wasm"? } },
  "edges": [ [ "<node>.<port>", "<node>.<port>" ] ],
  "policy": { "overflow": "drop_oldest"|"drop_newest"|"block", "queue": uint, "state_flush_s": uint, "restart": {"backoff_max_s": uint} },
  "permissions": { "token": tstr, "maxperm": uint },
  "layout": { <node_id>: [ x, y ] }   // 0.2.5: де редактор малює ноду; компілятор не зважає
}
```
Порти: `<node>.out`, `<node>.in`, іменовані `<node>.in.<name>` / `<node>.out.<name>` (у `expression` — `in.<input>`; у `alarm` — `out`, `event`).

Поля як виходи (0.2.15, ADR 0038): кожне поле ноди є також виходом, з якого може починатися ребро.
- Параметр `p` дає вихід `p` з ефективним значенням: з конфігу або default, а де є порт `in.<p>` — останній семпл на ньому. Вихід надсилає значення один раз на старті і далі на кожну зміну.
- Вхід `x`, що не є портом параметра (`in`, `reset`, `in.0`, …), дає вихід `x`. Він повторює кожен семпл на `x` до того, як нода його обробить.
- Назва виходу така сама, як у поля: `scale1.input_min`, `if1.in.0` (ребро ділиться на першій крапці: нода `if1`, порт `in.0`).
- Конфлікт назв: оголошений вихід ноди лишає свою назву; ехо входу йде перед ехо параметра. Тому параметр `reset` у `latch` (є вхід `reset`) не має виходу (`echo: false` у каталозі).
- Тип виходу: ехо входу — тип входу; ехо параметра — `number`, `bool`, `map` за типом параметра, інші (`string`, `dynamic`, `array`) — `any`. Крок 4 валідації перевіряє ці типи, як і решту.
- Ехо-вихід, з якого не йде жодне ребро, не будується: runtime не копіює для нього семпл.

УВАГА: ехо параметра надсилає значення на старті. Ребро з нього до `invoke` або `set` виконує команду при deploy.

`layout` належить редактору (ADR 0019): ключ — `node_id`, значення — два скінченні числа. Він не входить до конфігу ноди, тож переміщення ноди не скидає її стан при гарячій заміні.

Каталог типів нод для редактора: `dataflows/~act/node_types` (рівень `read`) повертає масив `{type, category, description, inputs, outputs, dyn_inputs?, dyn_outputs?, port_types, echo_inputs?, params: [{name, type, required, description, choices?, default?, editor?, port?, echo}]}`; `dyn_inputs`/`dyn_outputs` = `{param, prefix, default}` — порти, які дає параметр (`expression`: `in.<name>` з `inputs`; `wasm`: `inputs`/`outputs`).

Поля 0.2.15 (ADR 0038, лише додані):
- `params[].default` — типізоване значення для кожного параметра, що його має: число лишається числом, `choices` — рядком, список імен — масивом (`inputs` блоків: `["0", "1"]`). Без default поля немає.
- `params[].port` — `"in.<p>"`, коли в параметра є вхідний порт; інакше поля немає.
- `params[].echo` — `true`, коли параметр має вихід своєї назви; `false` при конфлікті назв (див. «Поля як виходи»).
- `port_types` — `{<port>: <type>}` (`number`, `bool`, `map`, `any`) для фіксованих входів і виходів, для динамічних портів з їхніми `default` і для ехо-виходів. Динамічні порти з іншими назвами мають тип `any`.
- `echo_inputs: true` — входи типу, що не є портами параметрів, повторюються як виходи. У типів без входів поля немає.

## Валідація (порядок, перша помилка зупиняє)
1. схема; 2. унікальність `node_id`, `[A-Za-z0-9_]+`; 3. тип ноди є в реєстрі, конфіг за схемою типу; 4. ребра → існуючі порти, сумісні типи; 5. ациклічність (цикл дозволений лише через `delay`); 6. rhai компілюється; 7. `permissions.maxperm` ≥ мін. рівня всіх `invoke/set`-нод і ≤ `write` (флоу не робить config-операцій); 8. ліміти пам'яті (`window.max_samples` сума); 9. (0.2.13) `key` кожної ноди `subscribe` і `liveliness` лежить під `wy/<site>/downstream`, `wy/<site>/dataflows` або `wy/<site>/storage` свого сайту (відносний ключ читається від `wy/<site>/`): не `sys`, `pub`, `upstream`, не інший сайт. Engine читає через сесію broker'а, якої ACL не бачить, тому правило перевіряє deploy, validate і старт збереженого флоу.

Помилка → `dataflows/<id>/~val = {state: 2 (error), error: "<path>: <msg>"}`; стара версія працює.

## `~val` флоу
`{0: {"state": 0 running | 1 stopped | 2 error, "error": tstr?, "version": uint, "since": uint, "deployed_by": tstr?}, 1: q, 2: t}`

`deployed_by` — суб'єкт, що задеплоїв поточну версію (`origin` запиту або `sub` токена). Флоу працює далі, навіть якщо деплоєр втратив права (ADR 0008); поле дає оператору знайти такі флоу.

## Живі значення (0.2.15, ADR 0038)
`dataflows/<id>/~act/watch` — рівень `read`, `stream: true`, `timeout_ms: 30000`. Аргументи: `nodes` (масив id нод; немає або порожній — усі; невідомий id — `invalid_parameter`), `max_hz` (число > 0 і ≤ 20, default 4).

Права: `auth` у `ptok` того, хто викликає (spec 04), має покривати читання кожного джерела флоу (`subscribe`, `liveliness`), як при deploy, і кожної цілі команд (вузол кожної ноди `invoke` і `set`, без `~act/<a>` чи `~set`). Вихід `invoke` несе відповідь цілі, а вхід `set` — те, що нода туди пише. Інакше — `permission_denied`. Помилка engine називає перший ключ, але SDK надсилає цей статус без тексту. Флоу без джерел і без цілей не потребує `auth`.

Рядки (CBOR map, текстові ключі; `[v, q]` — значення і код якості, як у `~val`):
1. перший: `{t, snapshot: true, nodes: {<node>: {in: {<port>: [v, q]}, out: {<port>: [v, q]}, params: {<p>: v}}}}` — кожна нода (або з `nodes`), усі три мапи завжди є; `params` — ефективне значення кожного параметра, що його має;
2. далі: `{t, snapshot: false, nodes: {…}}` — лише ноди і порти, що змінилися після попереднього рядка; порожні `in`/`out`/`params` пропущено. Не більше `max_hz` рядків на секунду; у межах періоду перемагає останнє значення;
3. heartbeat `{t, nodes: {}}` (без `snapshot`), коли 10 с не було рядка;
4. потік закінчується через 30 хв (ttl), при redeploy (останній рядок `{t, redeployed: <version>}`), при remove і при зупинці engine (без рядка). Редактор відкриває його знову.

Engine записує останній семпл порту, лише поки флоу має відкритий `watch` (або виклик `ports`). Тому порт без семпла від початку запису відсутній у `in`/`out`; змінна, що надіслала значення один раз на старті, з'явиться лише після наступного семпла. Записане лишається 5 с після закриття останнього `watch`. Без відкритого `watch` нода не робить жодної додаткової роботи.

Ліміти: ≤ 8 `watch` на флоу, ≤ 64 на сайт. Engine не бачить, що той, хто викликає, пішов: на ліміті новий `watch` того самого суб'єкта (`origin` або `sub`) закриває його найстаріший `watch` (на флоу, а на ліміті сайту — будь-який його); `watch` іншого суб'єкта отримує `busy`.

`dataflows/<id>/~act/ports` — рівень `read`, аргумент `nodes`, ті самі права; повертає рядок 1 (для інструментів без потоку: `wyrm-agent`, MCP). Значення портів у ньому є лише тоді, коли флоу має відкритий `watch`.

Значення ніколи не пишуться в лог вище `trace`.
