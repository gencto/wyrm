# 03 — `~val`

```
{ 0: v, 1: q, 2: t }
```
| Ключ | Тип CBOR | Опис |
|---|---|---|
| 0 `v` | за `~meta.type`: float64/int → number; tstr → string; bool; uint → enum index; map; array; bstr → binary; any → dynamic; null | значення |
| 1 `q` | uint | 0 good, 1 uncertain, 2 bad |
| 2 `t` | uint | uhlc timestamp джерела, мікросекунди Unix |

Розширений код quality (`bad/disconnected`, `uncertain/stale`, …) — **не тут**, а в attachment ключ 1 (`qual`), бо потрібен рідко.

## Правила
- `t` — час **вимірювання**, не публікації. Якщо джерело не має часу — час на боці конектора.
- Числа: encoder пише найкоротшу форму (int, якщо ціле; float32, якщо точно представиме — опція `cfg.precision`; інакше float64). Decoder приймає будь-яку.
- Пустий `~val` (вузол без значення) не публікується.
- Контейнери `~val` не мають.

## Історія
`get ~val?history=...` (параметри — 01) → CBOR array рядків `[t, v, q]` у порядку часу (масив, не map — компактніше для тисяч точок); з `agg` або `window` → `[t_start, value]` (без `q`; rollup пропускає `bad`).
- Відповідає історик брокера (`sys/history`, ADR 0014), лише для точок, які він записує. Storage на той самий запит віддає останнє значення (map): клієнт бере лише масиви (`ConsolidationMode::None`).
- Відповідь — один або кілька reply, кожен масив (≤ 5000 рядків); клієнт з'єднує їх за часом першого рядка. Точка записується, а в діапазоні рядків нема → один порожній масив. Точку ніхто не записує → жодного масиву.
- Помилка (діапазон, `agg`, `window`, wildcard у ключі, діапазон понад 5 000 000 рядків, зайнятий історик) → reply без payload з attachment `status` (04).
- Права — як у `subscribe`: ACL сесії на `~val` точки; `ptok` не потрібен (05).

Фікстури: `val_*`, `hist_raw`, `hist_agg`.
