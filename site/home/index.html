A live node tree on Zenoh

WYRM is one Rust binary, wyrmd: a Zenoh router with static plugins. It gives you what made DSA useful: a node tree, reactive list / subscribe / invoke, managed connectors, permissions and dataflows. WYRM Studio is the desktop app that sets up and runs the whole network. Zenoh itself stays unpatched and unforked.

01 · Principles

Zenoh is the transport. WYRM is the meaning.

1

Zenoh stays as it is

The semantics are key-space conventions, a CBOR attachment, SDKs and static plugins.

2

One binary, no .so plugins

Dynamic Zenoh plugins must match the router's ABI exactly. WYRM does not use them.

3

Extend with data and processes

New logic is a flow in dataflows/**. A new protocol is a link: built in, a process, WASM or another machine.

4

Nobody reads another's state

Only put / get / subscribe on keys with an attachment, even inside one process.

5

Security is not optional

TLS or mTLS everywhere except loopback. Secrets never enter the tree. The responder checks every ptok.

6

The broker owns only itself

A link declares its branch again on every connect. What is not declared again does not exist.

03 · Upstream and downstream

Sites stack into a chain

Every site runs its own broker. A site below connects to the site above, and the one above sees and commands the whole branch within each user's rights.

wyrmd link device values go up commands go down
  1. 1 · Dial outThe site below connects to the site above over QUIC + mTLS. A field site opens no inbound port, so NAT and the firewall stay closed.
  2. 2 · EnrollIt makes its own key and gets a broker:<site> certificate by CSR. A token admits it at once, unless it relays other sites: then it always waits for Authorize.
  3. 3 · Values go upThe site above reads downstream, dataflows, storage and sys below it. upstream_val_hz caps the sample rate.
  4. 4 · Commands go down~set and ~act go down with the caller's rights. Config actions only where allow_config is on. Signing keys follow every 10 s.
  5. 5 · One gatewayCentral reaches plant through edge (via). Its gateway serves all three sites to Studio and to wyrm-agent.

04 · Link modes

Four ways to run a link

A link serves its branch wy/<site>/downstream/<link>/**. Where its code runs is your choice: speed and one binary, or isolation and installs while the broker runs.

  1. 1 · Embedded

    Inside the broker

    A driver compiled into wyrmd, run as an in-process session. No network hop and one binary to ship. Every broker's scheduler, alarms, DQL, uplink and storage run this way.
  2. 2 · WASM

    Inside, in a sandbox

    A component in wasmtime: no files, no WASI, only the TCP addresses you list, with fuel, memory and time limits. Install it while the broker runs; a fault breaks only the component.
  3. 3 · Process

    Beside the broker

    The broker starts the link as a child process, watches it and restarts it with backoff. It has its own mTLS identity and reaches only its own branch and the grants you give it. The demo's Modbus process uses about 20–24 MB of RAM (macOS arm64).
  4. 4 · External

    On another machine

    Anything that speaks the link protocol with a certificate from the broker's CA: a field gateway or a device. A new link can wait in quarantine until someone authorizes it.

05 · Deployments

Pick the shape that fits

The same binary covers one box on a DIN rail and a fleet of plants. Start small: a site joins a chain later without changes to its links.

One box

One wyrmd on an industrial PC or a Linux ARM board: links, historian, flows and the gateway together.

For: a building, a production line, a lab.

Edge and central

Each field site runs its own broker and dials out to central. Central sees and commands every point, within each user's rights.

For: sites behind NAT, one control room.

Fleet with relays

Regional brokers relay many plants to the head office (via). When the link above drops, each site keeps running: its links, flows and history are local.

For: many plants, regions, one view on top.

Coming from IOT-DSA? The ideas you know, on a modern transport

The node tree, list / subscribe / invoke, links with Add / Edit / Remove actions, permissions and quarantine work as you expect. The Modbus link imports a dslink-java-modbus tree with import_dsa.

Fault tolerance A warm standby for a site that must not stop

A second broker on another host follows the first: the registry, flows, users, secrets, link data, packages, storage and history. It takes over after takeover_s (10 s by default) while a witness or an arbiter agrees. Links and clients name both endpoints and move by themselves. See the operations guide.

08 · Studio

One app for the whole network

WYRM Studio is the desktop app for the people who set up and run a WYRM network. It logs in to one gateway and works on that site and on every site below it, within your rights. Edits are staged first; nothing is written until you apply them.

Explorer

The live tree of a site: devices, points, values with quality, actions as forms built from the node's own meta.

Links

Install a link from a driver, a package or a repository; stop, upgrade and remove it; let a new one out of quarantine.

Flows

A block editor with live values, drag-to-bind wires, actions of the tree as blocks, and your own blocks.

History

Watch groups, trends, rollups and retention of the built-in historian.

Access

Gateway users, roles and their grants, and the audit of what was done.

Sites

The brokers above and below, tokens for a new site, platforms the site sends to.

System

The broker's own values, router traffic, the standby, the log and maintenance, with a list of what needs a look.

Errors you can act on

Every refusal says what the broker said and where to fix it; a form opens again with the failing field marked.

Built with Flutter. It runs on macOS today; Windows and Linux builds are next. English and Ukrainian. How to get it. The code is in studio/.

09 · Security

Rights on every request

Every write and every action carries a signed ptok. The responder checks it before the driver sees the call. The rules are in spec 04; to report a weakness, see SECURITY.md.

  • TLS · mTLSeverywhere except loopback; the broker runs its own CA
  • ACLgenerated from the registry of links, operators and sites
  • Quarantinea new link or broker waits for Authorize
  • Auditevery set and invoke, arguments as SHA-256
  • Secretssealed; never in the tree, never in the logs

12 · Quick start

Three sites, one command

The demo builds the broker and the simulators, starts the chain plant → edge → central and opens a gateway on each site. Then an agent plan adds a Modbus device, history and a flow.

# 1. Get the code
git clone https://github.com/gencto/wyrm && cd wyrm
# 2. Demo: plant → edge → central
examples/demo/run.sh --clean
# 3. Edge's tree through central's gateway
cargo build --release -p wyrm-link-agent --features cli --bin wyrm-agent
export WYR_GATEWAY_PASSWORD=wyrm-demo-1
target/release/wyrm-agent tree wy/edge/downstream
# 4. A plan: check first, then --apply
target/release/wyrm-agent run examples/agent/modbus-dataflow.json
target/release/wyrm-agent run examples/agent/modbus-dataflow.json --apply
