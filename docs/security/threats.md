# Threat model T1–T12: controls, evidence, status

Source of the threat list: wiki `05 Безпека/Модель загроз.md` (table "Загрози і контрзаходи").
Iteration 5 is done when the pentest checklist for T1–T12 is closed (wiki `07 План/Ітерації.md`).

Snapshot: 2026-10-20, commit `92f9bc9`, Zenoh 1.10.1. The tests ran on `92f9bc9` plus uncommitted workspace changes from another party (`Cargo.toml`, `Cargo.lock`: new member `links/mqtt`).

**Rule for "closed":** a control exists in the code **and** a passing test shows it.
"Partial" = a control exists, but a part of the wiki countermeasure is missing or has no test.
"Open" = no control.

**Verdict:** the iteration 5 criterion is **not met**. 2 threats are closed, 10 are partial, none is fully open.
One partial item (T2, REST plugin) was confirmed against a live `wyrmd` while writing this file.

## Test runs used as evidence

All the tests named below passed on 2026-10-20 (macOS, ARM64, debug build):

```
cargo test -p wyrm-link-sdk        # harness, guards, host, derive + unit tests
cargo test -p wyrm-admin           # acl, secrets, secret, registry, supervisor, control unit tests

cargo test -p wyrm-flow            # flow, nodes + script unit tests
cargo test -p wyrm-client          # tokens unit test
cargo test -p wyrmd --test e2e     # 13 end-to-end tests

cargo test -p wyr                  # flow::tests::proofs_per_target, missing_proof_names_the_target
cargo test -p wyrm-link-mock --test df slow_device_does_not_pile_up
```

No cited test was skipped. There are no tests yet for: driver panics, `origin`, `allow_bad`, the TLS handshake with
a foreign or missing client certificate, read-side rate limits, and the refusal of gateway/flow keys on `sys/**`.

## Pentest checklist

Run these checks against a live `wyrmd` in the `prod` profile with `tls/` and, for T12, two sites.
Each item gives the expected safe result. A different result is a finding.

Setup (all items):

- `SITE` = the site name, `BROKER` = the broker host, `DATA` = the `data_dir`.
- Our CA: `$DATA/pki/ca.pem`. Link certificates: `$DATA/links/<id>/link.pem` and `link.key`. Link token: `$DATA/links/<id>/token`.
- There is no command that issues operator certificates. For a CA-signed test certificate, sign it with `$DATA/pki/ca.key` (admin only):
  ```
  openssl req -new -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes -subj "/CN=probe-1" -keyout probe.key -out probe.csr
  openssl x509 -req -in probe.csr -CA $DATA/pki/ca.pem -CAkey $DATA/pki/ca.key -CAcreateserial -days 1 -out probe.pem
  ```
- Raw Zenoh client (Python `eclipse-zenoh==1.10.1`), used where `wyr` has no command:
  ```python
  import zenoh, sys
  conf = zenoh.Config.from_json5(f'''{{
    mode: "client", connect: {{ endpoints: ["tls/{sys.argv[1]}"] }},
    scouting: {{ multicast: {{ enabled: false }} }},
    transport: {{ link: {{ tls: {{ root_ca_certificate: "{sys.argv[2]}",
      enable_mtls: true, connect_certificate: "{sys.argv[3]}", connect_private_key: "{sys.argv[4]}" }} }} }} }}''')
  s = zenoh.open(conf)
  # then: s.put(key, b"..."), s.delete(key), s.get(key, payload=..., attachment=...)
  ```
  Save it as `zc.py`; call it as `python zc.py BROKER:7448 ca.pem cert.pem key.pem`.

| P32 | T12 | On the upstream side, subscribe to one slow point and one fast point of the downstream site with `upstream_val_hz: 1` | Expected safe: each link at up to 1 Hz. **Current result: one budget per link; a slow point of the same link as a fast one can still starve (ADR 0007).** |

## Known gaps

Most severe first. Each line names the threat and the ADR when the gap is already recorded there.

1. **REST plugin bypasses the ACL (T2, T11).** With `rest` set, any local process can put or delete `~val` in any link branch and add forged audit records under any link name on `sys/audit/<link>`. Both were confirmed live. The forged audit records carry `sub: claimed:<x>` and `link:<id>` from the key, so they cannot pose as admin records; a key inside the link subtree avoids the `key_outside_link` flag. No ADR records this; the project notes only say that REST cannot carry a `ptok`. Mitigation until fixed: do not set `rest` in `prod`.
2. **Peer CA can impersonate other sites (T12, ADR 0007) — closed 2026-10-23 (ADR 0015).** The QUIC listener trusts this site's CA alone, and that CA issues one `broker:<site>` certificate per admitted downstream site; no other CA can sign a peer identity here. Left: no revocation (a removed broker's certificate stays valid until it expires; it is held in quarantine, and its name never becomes an upstream site).
3. **Flows are not re-checked after a revocation (T5, ADR 0008) — accepted.** Proofs are checked only at deploy; stored flows redeploy on every broker build without proofs. Owner decision 2026-10-21: flows keep running until an operator stops them; `~val.deployed_by` names the deployer.
4. **No read-side DoS limits (T7).** `~meta`, `~val`, documents and wildcard fan-in have no rate limit and no result cap; the ACL has no wildcard limits.
5. **Replay window after restarts and no lifetime cap (T9).** The `jti` cache is in memory per responder and is lost on link restarts and ACL rebuilds; the verifier accepts any `exp`.
6. **Embedded driver isolation (T8).** No `catch_unwind`, no test with a panicking driver; no cgroup/seccomp for process links (rlimits and `no_new_privs` only).
7. **SecretStore key not bound to a TPM or keyring (T6, wiki iteration 5).** `secrets.key` sits next to `secrets.bin`; anyone who can read `data_dir` can decrypt.
8. **Flow `~def` is not linted for secrets (T6, T12).** Every requester and every upstream site can read flow definitions and state.
9. **Shared downsampling budget (T12, ADR 0007).** One `upstream_val_hz` budget per link per transport; a busy point can starve a slow point of the same link.
10. **Audit tail truncation not detectable (T11).** The HMAC chain has no external anchor, so removing whole records at the end of the WAL is accepted as a torn tail.
11. **`origin` not bound (T10).** It is passed as sent with any valid token, never mapped to the CN, and no test covers it.
12. **No flow or link definition history or rollback (T11).**
13. **Missing negative tests (T1, T11, T12).** No test for a missing or foreign-CA client certificate on `tls/`, for peer-CA isolation from `tls/`, or for the admin refusing gateway and flow tokens on `sys/**`.
14. **No `transport/link/protocols` whitelist (T1).** Only the listen endpoints limit the protocols.
15. **No certificate revocation (T3, ADR 0006).** Certificates live 1 year; retired ids compensate for removed links only. Process links are not adopted by PID after a broker restart (ADR 0006).
16. **Gateway users cannot deploy flows with command sinks (ADR 0008, 0009).** Not a security hole, but it pushes such deploys to key holders (`wyr --key`).

## Fixed since this review
- **REST bypass (T2, T11):** `rest` is refused unless `profile: "dev"` (the plugin runs inside the router, outside the ACL). Test: `plaintext_off_loopback_is_refused` in `crates/wyrmd/tests/e2e.rs`.
- **Flows with `config` (T5):** `permissions.maxperm` ≤ `write` (spec 06 step 7, spec 0.1.1). Test: `compiler_checks` in `crates/wyrm-flow/tests/flow.rs`.
- **Replay window (T9):** responders refuse tokens with `exp` more than `MAX_TOKEN_TTL_S` (15 min) ahead, which bounds replay after a restart clears the `jti` cache. Test: `long_lived_tokens_are_refused` in `crates/wyrm-link-sdk/tests/guards.rs`.
- **Flows from gateway users (ADR 0009):** the gateway signs per-target proofs with the user's grants. Test: `flow_deploy_proofs_come_from_the_user`.
- **Read storms (T7):** one read budget per link (`LinkConfig.read_rate_limit`, default 5000/s, burst 10 000; `~meta`/documents answer `rate_limited`, `~val` and fan-in get no reply) and at most `MAX_READ_ITEMS` (10 000) replies per wildcard `get` or `view=keys`. A read is first charged to one of 1024 per-key shards (5 % of the budget each), so a flood on one key fills its shard; a flood spread over many keys can still slow other readers, because reads carry no verified identity. Tests: `reads_are_rate_limited`, `read_flood_on_one_key_spares_others`.
- **MQTT secret redirection (T6):** `auth_ref` secrets are bound to the install destinations; runtime connection edits cannot send them elsewhere. Sparkplug state from the broker is capped. Tests in `links/mqtt`.
- **`tls/` listener negatives (T1, T3):** a client without a certificate or with a foreign-CA certificate gets no session. Test: `tls_listener_refuses_missing_and_foreign_certificates`.
- **Driver panic (T8):** every driver call (`start`, `on_set`, `on_invoke`, `reconfigure`, `stop`) runs under `catch_unwind`; a panic answers `internal_error`, marks all values `bad/driver_panic`, closes the link and stops its actor, so callers never hang and the broker keeps running. Test: `driver_panic_closes_the_link`.
- **Forged `origin` (T10):** with a valid token the responder keeps `origin` only if it equals `claims.sub` or is `<sub>/...`, otherwise it uses `claims.sub` (spec 0.1.3). Test: `origin_is_bound_to_the_token_subject` (P27).
- **Flow definition history (T11):** the flow store keeps the last 10 replaced definitions per flow; `<id>/~act/history` (`read`) lists them, `<id>/~act/rollback {version, proofs}` (`config`) redeploys one as a new version with the deploy checks of ADR 0008. Test: `history_and_rollback`. Link definitions have no history yet.
- **Capped signing keys (T5, T9):** links trust the flow engine key and every agent key only up to `write` (`LinkConfig.limited_keys`; `Verifier::with_limited`), so a stolen one cannot mint `config`. Agent keys are link secrets created by the admin; deleting the secret rotates the key on the next broker build. Tests: `limited_keys_are_capped`, `agent_key_is_trusted_capped_at_write`.
- **Agent and flow key scopes (T5, T12):** limited keys (`LimitedKey`) are capped and scoped: the flow and gateway keys to `wy/<site>/downstream`, each agent key to its link's `allowed_prefixes`. Agent links cannot be external (install, bootstrap and quarantine approval refuse it). Process links exit when the broker comes back, so the supervisor restarts them with a fresh `hello` and trust list. Tests: `limited_keys_are_scoped`, `agent_key_is_trusted_capped_at_write`.
- **Cut WAL tail (T11, P29):** `wyrm-state` `Store::with_anchor` keeps `<lsn> <mac>` outside the store after every write; on open an anchor ahead of the WAL, or the same LSN with another MAC, is refused (one record behind is a tolerated crash window). `wyrmd` `state_anchor_dir` (outside `data_dir`) anchors the registry and the audit journal. Tests: `anchor_detects_a_cut_wal`, `state_anchor_refuses_a_cut_wal`. The flow and gateway user stores are anchored too (`flows.head`, `users.head`). Fail closed: a store with records refuses a missing anchor (`wyrmd init-anchors` creates the anchors on purpose; the directory must already exist), and a failed anchor write stops further writes until it succeeds.
- **Link definition history (T11):** the registry keeps the last 10 replaced params per link (SCHEMA 4); `sys/links/<id>/~act/update` (config, linted, validated, restarts the link), `history` (config: params are control-plane data) and `rollback {rev}` (config). Links from `wyrmd.json5` are edited there. Test: `link_params_update_history_rollback`.
- **Offline verification (P29):** `wyrmd verify` (wyrmd stopped) checks every store — registry, audit, flows, gateway users, agent stores — for CRC, HMAC chain and anchor without changing it (`wyrm_state::verify`); a torn last record is reported, because without an anchor a crash and an edited last record look the same. Tests: `verify_reports_without_changing`, `verify_state_finds_a_tampered_wal`.
- **Agent token budget and store size (T7):** before each LLM call the agent holds the estimated input (one token per three bytes of the request) plus the output it may ask for, and sets `max_tokens` to that output, so a call overruns the daily budget only by the error of the estimate. The agent store is rewritten from its current state whenever its WAL passes 10 000 records, also while running. Tests: `reservation_is_checked_and_held_in_one_step`, `compaction_keeps_state_and_drops_history`, `budget_exhausted`.
- **FFI transport (T1):** `wyrm_open` (C ABI, Dart `WyrmFfi.open`) refuses plaintext endpoints off loopback and `tls/`/`quic/` endpoints; `wyrm_open_tls` (Dart `tls: TlsFiles(...)`) connects with mTLS and a client certificate from the broker CA. `wyr` and the FFI build their session from one function (`wyrm_client::endpoint::client_config`). Test: `open_over_mtls` (own CA connects, a foreign certificate does not). Owner decision 2026-10-21: no plaintext opt-in for the FFI.
- **Process link limits (T8):** before it connects, a process link sets hard rlimits on itself from the supervisor (`wyrm_link_sdk::limits`, `link_limits` in `wyrmd.json5`): no core dumps (the token and secrets would be in them), `open_files` (default 4096), `memory_mb` (default 1024, `RLIMIT_DATA`, Linux only: macOS refuses it), and `no_new_privs` on Linux. The binary applies them in `main` before the tokio runtime (`no_new_privs` is per thread and only new threads inherit it); `process::run` checks every thread in `/proc/self/task` and stops otherwise. A limit that cannot be set stops the link (fail closed). Test: `limits_hold_in_a_child`. Not yet: cgroups (CPU, memory of the whole tree) and seccomp.
- **Serial ports (T3, T8):** a modbus `serial_connection` opens only serial port names (`/dev/ttyS|ttyUSB|ttyACM|ttyAMA|…<n>`, macOS `/dev/tty.*` and `/dev/cu.*`, `/dev/rfcomm<n>`, `/dev/serial/by-id|by-path/*`, `COMn`; not `/dev/tty`, consoles `/dev/ttyN` or `/dev/ttyprintk`; no `..`): a `config` user cannot make the link open another device file, some of which act on open (a watchdog). Test: `only_serial_device_paths`.
- **Allow All Links (T3):** `sys/allow_all_links` (owner decision 2026-10-22, as DSA `allowAllLinks`) admits every CN signed by our CA over `tls` as an external link without approval. The risk is any leaked or forgotten CA-issued certificate: it gets its own `downstream/<cn>/**` branch at once. It never admits a retired, rejected, operator, peer-broker or downstream-site name (`admissible`), and the device still needs the link token from the broker's `data_dir` for `hello` (params, secrets, trusted keys). Off by default, `config` level, audited (`set_option`, `auto_install`), logged at start while on. `sys/enable_quarantine` off ignores unknown CNs. Tests: `admissible_cns`, `sys_values_and_admission_options`.
- **WASM links (T8, T12, ADR 0012):** a `wasm` link runs in the broker's process, sandboxed (ADR 0010): fuel, memory and a per-call time that includes host I/O, at most 4 connections. Its only import is `wyrm:link/tcp`, limited by the connection's `net` list (IP literals and ports; loopback, link-local, metadata and IPv6-embedded IPv4 need an entry of their class, so `0.0.0.0/0` does not reach the broker's own listeners), which only `config` can edit. No TLS, DNS or other sockets. Tests: `net_policy`, `driver_reaches_only_listed_addresses`, `driver_io_ends_with_the_call`, `driver_world_takes_point_components_and_refuses_other_imports`, `wasm_link_reads_a_device_over_tcp`.
- **Logs in `sys` (T6):** `sys/~act/get_log` and `sys/links/<id>/~act/get_log` (level `config`) return the last log lines of the broker (a ring of 5000 lines / 2 MiB, lines cut at 4 KiB) and of each process link (2000 lines / 1 MiB, its stdout and stderr). Whoever has `config` on `sys/**` reads them, so the rule "never log secrets, `ptok` or `~val` values above `trace`" now guards a remote read, not only the host's files. `log_level` values take level names only, never raw filter directives. Embedded links log inside their `link{id}` span; a driver task spawned without `in_current_span()` logs as the broker. Test: `logs_and_log_levels`, `link_levels_apply_to_spans_created_before`.
- **Link packages (T8, ADR 0011):** a `config` user (also through the gateway) can install a package from a zip (later Url, Git, Repository) and run its binary as a process link: code execution on the broker host as the broker's user. Owner decision 2026-10-22: no signing, as in DSA. Limits: the process link runs with rlimits, a cleared environment, its own data dir, its mTLS CN and the ACL of its own branch; the zip is unpacked in a temp dir with size and file limits, safe relative paths only and no symlinks, then renamed into place; a package for another link protocol is refused; every install and removal is audited with the zip's SHA-256 and source. Url, Git and Repository make the broker fetch from a URL a `config` user names (SSRF): HTTPS anywhere, plain HTTP only to loopback, `file://` git only in `dev`; the user sees only the status or a package error, and a `config` user can run code anyway, so this adds no right. Not yet: a separate uid, seccomp, signing. Tests: `unpack_check_commit`, `bad_packages_are_refused`, `repository_index`, `refs_and_urls`, `zips_a_directory_without_git`, `install_link_from_zip`, `install_link_from_url_repository_git`.
- **Link grants (T5, T8, ADR 0013):** a link can be a requester: `sys/links/<id>/~act/grant` (level `config`, audited as `link_grant`) or a package's `requester` list gives it `list`, `read` or `write` on `wy/<site>/downstream[/…]` or at most `read` on `wy/<site>/dataflows[/…]`; plain segments only, never `sys/**`, never `config` (`check_grant`). Process and external links get router ACL rules for the granted paths only (`grant_rules`); `~set`/`~act` need a `ptok` signed by the link's requester key, which every link trusts only up to the grant's level and only under its path (one `LimitedKey` per grant); the admin and the flow engine never trust it. The requester key signs only for `link:<id>` (`LimitedKey::subject`), so a link cannot write audit records in another subject's name; a package cannot ask for a whole `downstream` or `dataflows` root (an operator can grant one). Accepted: an embedded link runs on the broker's session and bypasses the ACL (it can read every branch without a grant, as before), so for it only the `ptok` check stands; a package install shows the grants it asked for in the result, and the user who installs a package with grants also grants them. The requester key is a link secret: sealed in `secrets.bin`, sent in `hello` to the process link, never logged; removing the link removes the key. Tests: `link_grants`, `link_grants_open_other_branches`, `link_grants_make_a_requester`, `bound_keys_sign_only_their_subject`, `hello_keeps_key_subjects`, `bad_packages_are_refused`.
- **Embedded historian (T4, T7, T12, ADR 0014):** `sys/history` records point values the broker's in-process session sees (no ACL on it), so who can add a watch can record any point of this site or a downstream site: every change needs `config` on `sys/**` and is audited (`history_group`, `history_watch`, `history_options`, `history_purge`); Get History needs `config` too (not `read`: a role with `read` on `sys` need not have `read` on the points), and `sys/history` does not mirror point values (no Last Written Value), only start and end dates. Watches never reach `sys/**` and take one plain key each (`check_watch_key`). A watch is not checked against the adder's rights on the point: `config` on `sys/**` is the root of trust (it can give itself any grant with Update Permissions or install a link), so a watch adds no right. A sample's time comes from its source: more than 5 min ahead or 31 days back is dropped (`plausible`), so a bad clock cannot create day files that retention and Auto Purge never reach. Resource bounds: 64 groups, 10 000 watches, 200 000 rows pending in memory (more are dropped and counted), 10 000 rows per Get History, intervals at least 100 ms; disk bounded by Auto Purge (default on, 1024 MiB kept free) and Retention Days, the current day is never deleted automatically. `data_dir/history` is data, not control state: no HMAC chain, not checked by `wyrmd verify`; a bad row is skipped on read. Reading a point's history (`~val?history=`, spec 05 0.1.10) needs what reading its value needs: the session ACL on `<point>/~val`, and through the gateway `read` on the point (op `history`); a read is bounded (100 000 rows, 5 000 000 scanned, 4 at a time, then `busy`). Tests: `history_records_and_answers`, `watch_groups_and_watches`, `logging_types_and_rebuilds` (implausible times, `~val?history=`), `history_follows_point_grants` (gateway), store tests.
- **Deauthorize (T3):** a deauthorized external link goes back to quarantine instead of being retired (owner decision 2026-10-22, ADR 0006). Its certificate stays valid (no CRL) but gets no rights; a held CN is re-admitted only by a manual Authorize, never by `allow_all_links`. Authorize `group` adds one `write` grant for a gateway role on the new link (audited as `update_permissions`); Deauthorize and Remove revoke every gateway grant on exactly `wy/{site}/downstream/<id>/**` that gives its role more than the role's other grants would (`Gateway::revoke_widening`: the Authorize grant or a widening one made by hand), so a CN authorized again does not inherit it; restrictive and neutral grants stay. The rule does not depend on stored state, so links from before it are covered. Tests: `revoke_widening_keeps_restrictive_grants`. Tests: `deauthorized_links_go_back_to_quarantine`, `authorize_and_deauthorize`.
- **Runtime peers (T12, ADR 0015):** a `config` user adds an upstream site in `sys/upstream` with its CA, the certificate it issued for us (CN `broker:<this site>` checked) and the key (checked against the certificate, sealed in the secret store as `peer:<site>`, written 0600 to `data_dir/pki/peers/<site>.key` for Zenoh, never in the registry, `~meta`, `~val`, the audit or a log; the endpoint names files, not base64). A downstream broker is admitted by Install Link ▸ Downstream Broker or by Authorize from quarantine (never by `allow_all_links`); its certificate goes to `data_dir/peers/<site>/` and the action result names the files without the key. Remove holds it in quarantine; a name ever issued (`Registry::issued_brokers`) is refused as an upstream site at runtime and at start. Every change is audited (`peer_add`, `peer_remove`, `peer_enable`, `install_broker`, `broker_remove`, `approve`). Tests: `runtime_peers_over_quic`, `downstream_brokers_issued_and_held`.
- **Runtime role grants (T5):** `sys` Update Permissions changes the gateway's role grants (ADR 0009). It needs `config` on `sys/**`, is audited, and cannot remove the last enabled admin's `config` on `wy/<site>/sys/**`. An admin can still widen a role (e.g. give `viewer` `config` on `wy/**`); that is the admin's right, visible in Get Permissions and the audit. Tests: `role_grants_change_persist_and_keep_an_admin`, `gateway_in_wyrmd`.
- **Peer presence (T12):** `upstream/<u>/connected` and `downstream/<d>/connected` come from liveliness tokens on `wy/<peer>/sys/broker`. The ACL lets a peer (and a link) watch our token and declare only its own: no ingress `liveliness_token` on our `sys/broker` key, and each upstream site has its own presence rules. A link id, an approved quarantine CN or a persisted runtime link equal to a downstream site name is refused (it would overlap `downstream/<d>`); the ACL also skips `link-<d>` rules. Test: `presence_tokens_by_direction`.
- **Connector credentials (T6):** as in DSA, a framework connection takes its password and TLS key as secret parameters of `add_connection`/`edit` (MQTT: `password`, `key_pem`; CA and client certificate as `ca_pem`/`cert_pem`). The framework seals its whole tree in `data_dir/framework.tree` (ChaCha20-Poly1305, per-link store key from the admin `SecretStore`, AAD = link id), never shows secrets in `~meta`, `export` or replies, keeps a secret on an empty edit field only while the `dest` fields stay the same, and lets new bootstrap params replace the stored tree. The admin lint also refuses `key_pem` and PEM private keys in install params. A password still goes in plaintext only to loopback. The `auth_ref` bindings cover the same destination fields (host, port, tls, `ca_file`, `ca_pem`), so an edit cannot point a bound password at a CA of the caller's choice (test `conn_secret_by_reference`). The store key cannot be rotated except by removing the link (`set_secret`/`delete_secret` refuse names that start with `.`). Tests: `runtime_edits_and_secrets_are_kept`, `password_in_the_connection`, `tls_with_ca_pem`, `process_link_keeps_runtime_edits`, `params_lint`.
