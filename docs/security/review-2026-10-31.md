# Code security review, 2026-10-31

A vulnerability analysis of the code this repository ships, done by reading the
code (no live pentest). Baseline: `docs/security/threats.md` (threat model
T1–T12, snapshot 2026-10-20). Gaps already listed there are not repeated; this
file covers what was added since (package install, peer enrollment, signer
propagation, protocol codecs, WASM/portable links, scheduler, storage, history,
MCP/agent, FFI) and re-checks the older controls where they interact with new
code.

Snapshot: commit `b97d0b2`, Zenoh 1.10.1, wasmtime 40.0.4, rustls 0.23.45.

**Rule for severity.** *High* = a realistic attacker gains rights or control
they do not hold, or the system is guaranteed to fail; *Medium* = needs an
already-privileged position (a `config` user, an upstream broker, a link
certificate) or yields a denial of service of a whole site; *Low* = hygiene,
narrow preconditions, or defence in depth; *Info* = worth knowing, no action
required.

**Verdict.** No remotely exploitable memory-safety or authentication bypass
was found in WYRM's own code: every crate on a network path has
`#![forbid(unsafe_code)]`, the in-crate protocol decoders (BER, SNMPv3 USM,
TPKT/COTP/S7, BACnet, Modbus, Prometheus text, JSONPath subset, CBOR) bound
every length and depth, and no panic on wire data was found. The findings are
in the *design* layer: approvals not bound to arguments, confused deputies,
missing rate limits around authenticated callers, a same-uid process model,
certificate lifetime, and an outdated WASM runtime with published sandbox
escapes.

## 2. Dependencies (`cargo audit`, 2026-10-31)

33 advisories against `Cargo.lock`. CI runs neither `cargo audit` nor
`cargo deny` (`.github/workflows/ci.yml`).

### DEP-1 — High — wasmtime 40.0.4

20 advisories, among them sandbox escapes and miscompilations that matter for
this project's targets:

- RUSTSEC-2026-0096 "Miscompiled guest heap access enables sandbox escape on
  aarch64 Cranelift" and RUSTSEC-2026-0379 "Cranelift backend on aarch64 can
  jump to incorrect target on large `br_table`" (CVSS 9.9). The reference board
  is 4-core ARM64; Cranelift is the only enabled backend
  (`Cargo.toml`: features `runtime, cranelift, component-model, std`).
- RUSTSEC-2026-0380 bit-packing miscompilation (all targets).
- Component-model issues: RUSTSEC-2026-0091/0092/0093 (string transcoding OOB
  write/read), 0085 (flags lifting panic), 0316 (record lifting beyond fuel),
  0327, 0363 (handle tables charged to no limit), 0424 (borrowed resources).
  WYRM uses components (`wyrm:flow/node`, `wyrm:link/driver`, `wyrm:app`).
- Winch-only advisories (0086, 0089, 0094, 0095) and the WASI one (0269) do
  not apply: Winch and WASI are off.

ADR 0023 states WASM is fault isolation for code installed by someone with
`config`, not a sandbox for hostile code. Even so, `put_artifact` on
`dataflows` and package installs from a repository/URL/git are reachable by
`config` users who are not admins, and a miscompilation escape turns a
`config` user into the broker uid (see ADM-1 for what that means).

Fix: the pin comment says "MSRV 1.89 → 40.x". wasmtime 36 is the LTS line:
`36.0.20` has `rust-version = 1.86` (checked with `cargo info`) and patches
every advisory above. Move to `wasmtime = "=36.0.20"` (component-model API is
the same major shape; expect small changes in `ResourceLimiter`/`Store`
signatures). Then add `cargo audit` (or `cargo deny check advisories`) to CI.

## 3. Admin, PKI, packages, enrollment (`crates/wyrm-admin`)

### ADM-1 — High — process links share the broker's uid and filesystem

`crates/wyrm-admin/src/supervisor.rs:240-253` spawns the link with
`env_clear()` and the allow-listed env, but no `uid()`/`gid()`, no
`current_dir`, no namespace. `crates/wyrm-link-sdk/src/limits.rs:55-95` sets
only `RLIMIT_CORE/DATA/NOFILE` and `no_new_privs`. The link's `data` directory
is 0700 (`control.rs:1012-1028`) but owned by the same user as
`data_dir/pki/ca.key`, `secrets.key`, `secrets.bin`, `state.key`,
`links/*/token`, `operators/*.key`.

Scenario: code execution inside any process link (a bug in `tokio-modbus`,
`async-opcua`, `rumqttc`, `prost` or `hyper` triggered by a hostile device; a
malicious package; a wasmtime escape, DEP-1). The child reads `ca.key` and
mints a certificate for any CN (`admin`, any link, `broker:<site>`), decrypts
every device credential with `secrets.key`, and rewrites the WAL with the HMAC
key. The Zenoh-side mTLS identity and ACL (T8) do not help, because the attack
never goes through Zenoh.

Fix: a dedicated unprivileged uid/gid per link (`Command::uid/gid`), chown the
link's `data`, `token`, `link.{pem,key}` to it, keep the rest of `data_dir`
0700 to the broker user, and move `ca.key`/`secrets.key`/`state.key` to a
broker-only subdirectory. Longer term: systemd `DynamicUser=` or a mount
namespace. Known gap 6 (cgroup/seccomp) does not cover this.

### ADM-2 — Medium — `via` is chosen by the enrolling broker

`control.rs:4766-4909` (`enroll`): `via` comes from the anonymous request and,
on the token / `allow_all_links` path, goes straight to `admit_broker`
(`:4863-4871`). `via_free` (`:4658-4676`) checks only that the names are
unused; `registry.rs:1243-1275` stores `csr_pem` (≤16 KiB) and `via` with no
count cap; `acl.rs:470-480` gives `broker-<d>` `ALL` on `wy/<v>/**` for each
name.

Scenario: one admission token (or `allow_all_links`) and `via = [plant, cell,
…]` lets the enrolling broker publish a fake `wy/plant/**` that this site and
every site above accept, and the real `plant` is later refused. A multi-MB
`via` lands in the WAL, the quarantine node attributes and the generated ACL.

Fix: admit with `via = []` on the token/auto path (relays only through
Authorize, as ADR 0015 words it), or bind the token to `{site, via}`; cap
`via.len()` and the enroll request before `apply`.

### ADM-3 — Medium — audit flood from any link certificate

`control.rs:5427-5491` (`watch_audit`): every `put` on
`wy/<site>/sys/audit/<link>` becomes an `AuditRecord` whose `sub`, `op`,
`key`, `detail` are copied without a length cap or rate limit;
`wyrm-state` accepts 16 MiB records; `audit.rs:41-47` keeps the last 1000 in
memory. The SDK's flood suppression is client-side; a raw Zenoh client with
the link's certificate bypasses it.

Fix: cap each text field (~256 B), drop oversized payloads before `apply`, a
token bucket per link in `watch_audit` with a `suppressed:<n>` record.

### ADM-4 — Low/Medium — serialised admin actor

`run_driver` handles one `Cmd` at a time (`wyrm-link-sdk/src/runtime.rs:444-500`).
`install_url`/`install_git` await the download (90 s) or clone (120 s) inline
(`control.rs:3390-3450`); `hello` (`:3995-4004`) runs argon2id (19 MiB, tens
of ms) on the actor without `spawn_blocking`. A `config` user with a slow
install host freezes `hello`/`enroll` for everyone for up to 120 s per call.

Fix: run download/clone/unpack in a spawned task and answer through the
`ReplySink`; `spawn_blocking` for argon2.

### ADM-5 — Low/Medium — agent signing key replaceable through `set_secret`

`control.rs:4150-4170` accepts any `[A-Za-z0-9_-]{1,64}` secret name including
the agent key (`agent_key_ref`, `:931-939`); `agent_key_of` (`:941-953`) takes
a raw or hex seed; `reload_if_agent` (`:4194-4204`) rebuilds so every link
trusts it at `write` with `subject: None` (`:900-929`). A role with `config`
only on `wy/<site>/sys/links/<agent>/**` sets a known seed, widens
`allowed_prefixes`, and signs `write` tokens with any `sub`.

Fix: store the agent key as an internal `.`-prefixed secret (as
`.requester_key`, `.store_key`, which `secret_name` refuses) and bind it to
`subject: Some("link:<id>")`.

### ADM-6 — Low — `install_url` fetch policy

`fetch.rs:27-29, 56-58`: `https://` to any address (RFC 1918, link-local);
`redirect()` (`:71-77`, loop `:157-160`) follows `Location: http://127.0.0.1:…`
(scheme downgrade to loopback). No `sha256` argument, unlike `install_repo`.
Blind (the body is only unpacked). Fix: refuse loopback/private targets outside
`dev`, refuse downgrade on redirect, optional `sha256`.

### ADM-7 — Low — `SecretStore::open` swallows read errors

`secrets.rs:68-69`: `Err(_) => Db::new()`. A transient `EIO`/`EACCES` on
`secrets.bin` starts with no secrets, and the next `set` (e.g. `ensure_store_key`
at install) rewrites the file with that single entry. Fix: only
`ErrorKind::NotFound` → empty; anything else fails the start.

### Info

- I-ADM-1: `Pki::issue` keeps existing `<name>.{pem,key}` without checking
  CN/SANs (`secret.rs:138-141`); `not_before` is 1975. See D-1.
- I-ADM-2: `git.rs:314-317` returns git stderr verbatim (temp path); `file://`
  clones in `dev` read any local directory.
- I-ADM-3: `token_id` compares SHA-256 hex with `==` (`control.rs:661-668`).
- I-ADM-4: supervisor inherits the broker's CWD and `PATH`; `eprintln!` of
  child output (`supervisor.rs:67`) is rate-unbounded and panics on a closed
  stderr, which would stall the drain task and then the child on a full pipe.

### Checked and sound

Zip unpack (`packages.rs:184-313`: `enclosed_name`, symlinks refused, 64 MiB
zip / 256 MiB unpacked / 1000 files, random temp dir, single rename, tests for
`../evil` and symlinks); repository index (SHA-256 before install, relative
URLs confined); git (`--` before URL, ref validated, `protocol.allow=never`,
hooks off, no submodules, `env_clear`, timeout); downloads (webpki roots,
HTTP/1.1, 3 redirects, `Limited` body); CSR handling (≤16 KiB, CN must equal
`broker:<site>`, fresh params, client-auth EKU, reserved names, 64 waiting,
10-min expiry, conflicting key never swaps in); CA (P-256, path length 0, keys
`create_new` 0600); SecretStore (ChaCha20-Poly1305, random 96-bit nonce,
`Zeroizing`); link tokens (32 random bytes, argon2id, PHC verify); generated
ACL (default deny, CN+`tls` bound, no path for link `b` into `a` or `sys/**`);
registry ops re-validated on replay; no `unwrap`/index on untrusted input;
`#![forbid(unsafe_code)]`.

## 4. Gateway (`crates/wyrm-gateway`)

### GW-1 — Medium — audit record per failed login, including rate-limited

`lib.rs:619-626` records `LoginFailed{reason: "rate_limited"}` for every
refused attempt; `wyrmd/src/lib.rs:1265-1280` → `ctl.record` →
`Store::apply` with `sync_data()` per record (`wyrm-state/src/lib.rs:321`)
under the global audit mutex shared with every link `set`/`invoke`. An
anonymous client at line rate costs one fsync per 64-byte request and grows
the HMAC-chained WAL without bound; the hashing semaphore (4 permits) is held
during the record (`http.rs:313-318`).

Fix: no record for rate-limited attempts; one summary record per `(user, ip)`
window (as the SDK's `suppressed:` does); check the limiter before taking a
permit (GW-7).

### GW-2 — Medium — no per-user caps on sockets, streams, one-shots

`ws.rs:52-57`: limits are per socket (64 streams, 32 in flight). Tickets are
capped only while live (8 per user) and consumed on redemption, so sockets are
unbounded per user; each may subscribe `wy/<site>/**` 64 times (served by a
real subscriber plus a stored-value `get` of the site, filtered per sample).
`history.limit` is user-chosen (`ws.rs:385`). A `viewer` can exhaust gateway
memory, router fan-out and the links' shared read budgets.

Fix: per-user socket cap (~8), token bucket per user for one-shots and stream
opens, cap on total subscriptions per user, server-side `history.limit` cap.

### GW-3 — Low/Medium — grants on a downstream site's name

`lib.rs:372-377` (`as_own`) rewrites `wy/<d>/x` → `wy/<site>/x` before every
read check, so a grant written as `wy/<d>/…` (accepted by `set_grant`,
`:556-565`) never matches a read. The write token keeps such grants
(`:131-144`) and `tokens.rs:382-392` matches them on the original key. A role
`[wy/edge/**: none, wy/**: config]` reads everything on `edge` through the
gateway while the `edge` responder refuses writes. Fix: refuse grants whose
first segment is a downstream site name, or evaluate both keys and take the
minimum.

### GW-4..7 — Low

- GW-4: sessions are stateless HMAC tokens valid until `exp` (default 8 h, up to
  7 d); `jti` minted (`session.rs:127-133`) but never checked; no
  `/api/logout`, no self-service password change (all `/api/users/*` need
  `Admin`). Fix: logout deny-list by `jti` until `exp`.
- GW-5: `set_grant` keeps one `config`-on-`sys` user (`lib.rs:571-582`);
  `set_roles`/`set_disabled`/`remove_user` do not. Availability only.
- GW-6: `limit.rs:52-57` 5 failures per `(user, ip)` and 20 per ip per minute,
  no per-user budget across addresses, no trusted-proxy list (good: XFF is not
  trusted). Behind one TLS-terminating proxy 20 bad logins lock everyone out.
- GW-7: the limiter check and audit write run inside the 4-permit argon2
  semaphore (`http.rs:313-318`); spraying distinct `(user, ip)` pairs costs one
  argon2 each and queues legitimate logins. Fix: limiter before permit,
  `try_acquire` → 503.

### Info

- I-GW-1: the gateway key is added to the admin responder's `admin_keys`
  uncapped (`control.rs:1577-1580`); links trust it at `config` on
  `downstream`, storage at `config`, the flow engine as an admin key. Only the
  user's grants limit it (ADR 0009). `README.md` and `CLAUDE.md` still say the
  admin does not trust it — stale. Whoever reads `data_dir/gateway/gateway.key`
  is a full administrator; no rotation procedure.
- I-GW-2: no HSTS/security headers; bearer-only auth makes CSRF and cross-site
  WebSocket hijacking inapplicable; ticket in the URL is single-use, 30 s,
  128-bit. `Denied` audit records copy the user-supplied key (up to 64 KiB).

### Checked and sound

argon2id with fresh salt and a dummy hash for unknown users; same message for
bad password and disabled; HMAC-SHA-256 sessions with derived key,
constant-time verify, `gen` bump on password change/disable; tickets 16 random
bytes, single use, bound to the session; bootstrap password removed from the
environment and checked; key files `O_EXCL` 0600; grants first-match with `max`
cap, `wy/<site>/` boundary, Zenoh key validity, no `~` segments; `sys/**` only
with a `sys` grant; `POST /api/invoke` authorises before reading the body
(64 MiB, 10 000 items, two concurrent); CBOR depth 32; no secrets in logs; Dart
client no `badCertificateCallback`, session in memory only.

## 5. Link SDK, core, state, storage, history, flow

### SDK-1 — Medium — replay cache filled before the grant check

`wyrm-link-sdk/src/auth.rs:157-162`: `remember(jti)` runs before the grant
lookup; `remember` (`:171-184`) fails closed for everyone at 65 536 entries
until entries expire. `runtime.rs:913-918` verifies any token present on a
`~meta` read, and `set`/`invoke` verify before the per-caller limiter
(`:1047-1060`, `:1083-1096`). Reads are limited only by the link-wide 5000/s
budget.

Scenario: any gateway user (the gateway key is trusted by every link; the user
needs no grant on the target link), a requester link or a flow sends ~65 k
token-bearing `~meta` reads with `exp = now + 15 min` (~13 s). Every later
`set`/`invoke`/restricted read on that link, and `proves_targets` in the flow
engine, is refused until the entries expire; repeatable.

Fix: grant check before `remember`; per-subject limiter keyed by `claims.sub`
after signature check but before insert; per-subject insert quota or LRU by
`exp` instead of fail-closed for all.

### FLOW-1 — Medium — flow sources are unrestricted

`wyrm-flow/src/nodes.rs:200-204, 218-222` accept any `key` for `subscribe` and
`liveliness`; `Io::full_key` (`:388-394`) keeps `wy/…` as written; the engine
runs on the broker's in-process session (`engine.rs:214`), which no ACL sees.
Only command sinks are restricted (`engine.rs:651-661`: `downstream/`,
`storage/`). A `publish` node republishes the input as
`dataflows/<id>/nodes/<n>/~val`.

Scenario: a role with `config` on `dataflows/**` and nothing on `sys/**`
deploys `subscribe wy/<site>/sys/audit/*` → `publish` and reads the audit
stream, `sys/status`, `sys/signing_keys`, any downstream site's `sys/**`
reachable from this broker, and any point it has no `read` grant on.

Fix: in `def::check` require source keys relative or under own-site
`downstream/`, `dataflows/`, `storage/`; never `sys/`, `pub/`, another site;
or a read proof per source key like `proves_targets`.

### SDK-2..6, FLOW — Low

- SDK-2: `Verifier::verify` (one `verify_strict` per admin key, then per limited
  key) runs before `limit(None, path)` (`runtime.rs:1047-1050`, `:1083-1088`).
  Transport-authorised peers (upstream brokers, requester links, the gateway)
  burn ~1 ms CPU per garbage token, uncapped. Fix: charge the anonymous bucket
  before `verify`.
- SDK-3: `put_artifact` (`engine.rs:794-812`) takes `bytes` of any size (64 MiB
  via `/api/invoke`), compiles it, writes `<flow dir>/artifacts/<sha>.wasm`;
  nothing deletes or counts artifacts. `Host.compiled` (`wasm-host/src/lib.rs:466`)
  and `Artifacts.loaded` (`artifacts.rs:18`) only grow; `forget()` is never
  called. Fix: 16 MiB cap, per-site quota, GC of unreferenced artifacts, LRU
  caches.
- SDK-4: `def.rs` bounds only `window.max_samples`; a `config` user deploys
  thousands of 10 ms `timer` or `wy/**` `subscribe` nodes, each a task and a
  Zenoh subscriber. Fix: cap nodes, edges, subscriptions per flow and per site.
- SDK-5: `runtime.rs:906-910` returns `not_found` before the `restricted` check,
  so anonymous reads distinguish existing restricted nodes. Same in `doc()`.
- SDK-6: `driver/persist.rs:182-207` seals `{boot, tree}` with AAD
  `wyrm-tree:<link>`; `load` accepts any older file (rollback restores removed
  connections and old sealed secrets). The portable app store
  (`wyrm-link-portable/src/store.rs:107-118`) likewise binds only the key name.
  Needs `data_dir` write (same trust zone as known gap 7). Fix: monotonic
  generation in the sealed payload.

### Info

- I-SDK-1: `open_actions` match by name on any node of the link
  (`runtime.rs:1118`); make them `(path, action)` pairs.
- I-SDK-2: `iat` decoded but never checked (`auth.rs:146-153`).

## 6. Protocol connectors (`links/*`)

All eight crates have `#![forbid(unsafe_code)]`. No `unwrap`/`expect`/`panic!`
on wire data in non-test code; no malformed byte sequence was found that
panics any in-crate parser (BER, SNMP msg, TPKT/COTP/S7, BACnet tag/NPDU/APDU/
BVLC, Prometheus text, JSONPath subset). Third-party decoders (`tokio-modbus`,
`async-opcua`, `rumqttc`, `prost`) were not audited; LNK-2 is the mitigation
gap if one of them panics.

### LNK-1 — Medium — HTTP link as an SSRF primitive

`links/http/src/client.rs:49-106` (`Origin::parse`) accepts any
`http(s)://host[:port]`; loopback is special-cased to *relax* the plaintext
credential rule (`lib.rs:339`). `try_request` (level `config`) returns status,
headers and up to 64 KiB of body (`lib.rs:1558-1664`); the write path POSTs an
operator template. With `rest` on (`dev`, loopback), an embedded `http` link
reads `http://127.0.0.1:<rest>/wy/<site>/sys/**` with no ACL; on cloud hosts
`169.254.169.254` returns instance credentials.

Fix: refuse (or require `allow_internal: true` plus a status note) base URLs
whose *resolved* address is loopback, link-local, unspecified or RFC 1918;
apply it on the resolved `SocketAddr` list in `connect()` (`client.rs:276-291`)
so DNS cannot bypass it; never the broker's own `rest`/gateway ports. The same
rule fits `links/prometheus` and the agent's `api_base` (AI-3).

### LNK-2 — Medium (latent) — owner-task panic freezes a connection as "good"

`wyrm-link-sdk/src/driver/framework.rs:1515-1527` spawns `owner::<D>` with a
plain `tokio::spawn`; no `catch_unwind` in `driver/*.rs`; the `JoinHandle` is
only ever aborted (`:1782`). After a panic the tickers get
`TrySendError::Closed`, reset `inflight` and keep sleeping (`:1874-1884`,
`:1914-1916`); the quality ladder lives in the dead owner, so no
`uncertain → bad` transition is published and `status` stays `Connected`.
This violates the "honest quality" rule in CLAUDE.md; in a process link the
process survives, so the supervisor sees nothing.

Fix: `AssertUnwindSafe(..).catch_unwind()` around each driver call in the
owner; on `Err` mark the connection `Failed`, `mark_all(Bad, "driver_panic")`,
reconnect with backoff; tickers treat `Closed` as fatal or `ConnRun` watches
`owner.is_finished()`.

### LNK-3..6 — Low

- LNK-3 (snmp): `client.rs:642-667` judges `private` from `msgFlags`; an
  HMAC-valid message with `FLAG_PRIV` and a *plain* scopedPDU is accepted on an
  authPriv session. Only the agent (or an auth-key holder) can produce it.
  Fix: reject `ScopedData::Plain` when `priv_key.is_some()`.
- LNK-4 (snmp): unauthenticated REPORTs with the matching msgID fail the
  request (`client.rs:686-751`); msgIDs are sequential (`:369`). The socket is
  `connect()`ed, so the attacker must spoof the agent's address. Optional:
  treat such reports as `Rejected` and keep waiting; random initial ids.
- LNK-5 (opcua): `pki.rs:400-422` writes a supplied `key_pem` to
  `private/user-<hash>.pem` (0600, removed by `KeyLease::drop`, swept at
  start) because async-opcua reads keys from files. Documented residual risk.
- LNK-6 (modbus slave): `slave.rs:74` `MAX_MASTERS = 16` per connection, no
  per-source cap; one host keeps 16 sockets alive with one request per
  `master_idle_s`. Default listen is loopback with a warning when wider. Fix:
  per-source-IP cap or `allowed_masters`.

### Info

- I-LNK-1: OPC UA mode/policy `None` allowed off loopback for anonymous only;
  identities over an unsecured channel are refused; status note shown.
- I-LNK-2: BACnet/S7/Modbus reply matching uses sequential ids and source
  identity; inherent to the protocols; timed-out Modbus requests force a reopen.
- I-LNK-3: `links/mqtt` takes `ca_file` (a broker-host path) while http/
  prometheus take `ca_pem` inline; a `config` operator can probe for file
  existence; harmless but inconsistent.

### Checked and sound

SNMP: definite lengths only, OID arcs bounded, HMAC `verify_truncated_left`,
RFC 3414 key localisation with test vectors, AES-CFB IV boots‖time‖salt from a
random-start counter, timeliness window, engine pinned, rediscovery
rate-limited, first reply used only to set the clock. S7: TPKT/COTP/S7 lengths
checked, item counts matched, 64 KiB PDU cap, every I/O under timeout. BACnet:
`checked_add` bounds, constructed depth 16 (tested at 100 000), BVLC length =
datagram, segmented ComplexACK refused, Forwarded-NPDU origin only from the
configured BBMD, I-Am capped and confirmed by ReadProperty, random-frame fuzz
test. Modbus: `get(..n)` slicing, slave request sizes and address ranges
checked, writes validated against every overlapping point before any state
change, queue 64 with 1 s deadline. HTTP: rustls/ring, `insecure_skip_verify`
explicit and surfaced as a permanent status note, custom verifier still checks
signatures, credentials over `http://` only to loopback unless noted, sensitive
headers never echoed, secrets masked in every encoding, JSONPath iterative with
512/32 caps, template substitutes a JSON-encoded value, redirects ≤3 same
origin, no redirects on writes, `Accept-Encoding: identity`. OPC UA:
`verify_server_certs(true)`, TOFU pinned only after an activated session, pin
mode exact, userinfo/query in endpoint refused, keys 0600/0700, supplied key
checked against the cert. Prometheus: body capped on the wire and after gzip,
line/label/name/value/series caps, reserved headers blocked. MQTT: no
skip-verify option, password plaintext only to loopback, `auth_ref` secrets
bound to install-time destinations, 256 KiB packets, Sparkplug state bounded,
`bdSeq` matched, rebirth rate-limited.

## 7. WASM host, portable links, scheduler, packaging

### WASM-1 — Medium — capabilities and grants applied at install without accept

`packages.rs:148-178` accepts manifest `capabilities` (net, store, memory
≤512 MiB, call ≤10 s) and `control.rs:3841-3867` applies them as the link's
params and then `set_grant` for every `requester` entry (whole roots, `sys`,
and `>read` on dataflows refused; anything else up to `write` on any named
link). The installer sees them only in the result message. Repository index
entries are SHA-256 pinned, not signed.

Scenario: a compromised repository or URL ships `acme 1.1` with
`capabilities.net = ["0.0.0.0/0:443"]` and `requester = [{path:
"wy/<site>/downstream/plc", level: "write"}]`; an admin upgrading the package
grants egress and PLC write without being asked.

Fix: a preview result (manifest capabilities + requester diff) and an explicit
`accept` argument, or a "pending capabilities" state; refuse upgrades that
*widen* `net`/`requester` unless accepted; consider signing repository indexes.

### SCH-1 — Medium — embedded scheduler as a confused deputy

`wyrmd/src/lib.rs:969-971` starts the embedded scheduler with a requester key
scoped `write` on all of `wy/<site>/downstream` (`control.rs:767-777`).
`add_target`/`edit_target` (`links/scheduler/src/targets.rs:1381`, `:1433`) use
`who` only to record `by`; there is no `.may(` anywhere in the scheduler. A
role with `config` on `downstream/scheduler/**` and nothing on
`downstream/plc` targets `plc/valve` and gets it written at the next transition
(or at once via override), signed `link:scheduler`; the PLC's audit names the
scheduler.

`docs/scheduler.md` §10 documents this as the current rule ("an owner decision
is still open", ADR 0022 ruling 6). Recommended decision: require
`who.may(point, Write)` (and `read` on `feedback`) in `add_target`,
`edit_target`, `import`, or give the embedded scheduler per-link grants like
the packaged ones.

### WASM-2, WASM-3 — Low

- WASM-2: `buffer.rs:298-334` pushes decoded `NodeMeta`/`Sample` unchecked and
  `LinkCtx::declare_node`/`update_sample` have no size bound; an app can keep
  10 000 nodes with multi-MB `last` samples in the SDK tree, `mem` storage,
  history and every subscriber. Fix: cap `Sample`/`NodeMeta` CBOR at ~64 KiB
  in `BufferHost`.
- WASM-3: `wyrm-flow/src/runtime.rs:179, 235`: the `wasm` node's `process` (up
  to 100 ms wall per call, re-instantiate after a trap) runs on a tokio worker;
  `Artifacts::get` compiles on the caller's thread and `compile()` at
  deploy/validate holds `shared` (`engine.rs:820`). Fix: `spawn_blocking` for
  `process` and compiles; warm the cache off the lock.

### Info

- I-WASM-1: sealed app store has no anti-rollback (see SDK-6).
- I-WASM-2: a `[64:ff9b::]/96:p` entry makes NAT64-embedded IPv4 reachable;
  policy expressiveness only.

### Checked and sound

Engine: `default-features = false`, no WASI/threads/cache, `consume_fuel`,
`epoch_interruption`, 10 ms ticker; `load()` rejects any import but the
world's one; fresh fuel, epoch deadline and host-I/O deadline before every call
including `instantiate`/`init`; `ResourceLimiter` sums memories (≤512 MiB),
tables ≤10 000, instances 16; store dropped on any trap, re-instantiated or
restarted with jittered backoff; buffered commands of a failed event discarded;
`NetPolicy` matches IP literals only (no DNS → no rebinding), IPv4-mapped
flattened, loopback/link-local/metadata/multicast/NAT64 need an entry of the
same class, `0.0.0.0/0` never reaches loopback, `net` is a `config` edit;
`BufferHost` 1000 commands/timers/subs, 100 in flight, keys ≤256 B / ≤10 000,
`check_key` confines to `wy/<site>/` and the link's grants, node paths
relative and validated; `Who` built only from the SDK's verified `Caller`;
sealed store ChaCha20-Poly1305 random nonce, SHA-256 file names, tmp+fsync+
rename; artifacts re-hashed on every uncached `get`, 16 MiB, `put_artifact` at
`config`; package/component names `[A-Za-z0-9._-]` ≤64; hot swap by rename
with generation check; scheduler ≤800 commands/event, node budget 9500, ≤20
targets/schedule, ≤50 writes in flight, watchdog with clock-step detection.

## 8. Daemon, peers, enrollment, CLI, FFI (`crates/wyrmd`, `tools/wyr`, `crates/wyrm-ffi`)

### D-1 — High (availability) — certificates issued once, 365 days, never renewed

`secret.rs:139` (`Pki::issue`): `if files.cert.exists() && files.key.exists()
{ return Ok(files); }` — `broker-server`/`broker-client`, every link cert and
every offline downstream cert are issued once; `:182-183` `not_after = now +
365 d`. `configure_zenoh` (`control.rs:1365-1375`) feeds them to every
`tls/`/`quic/` listener at every rebuild without an expiry check. On the
enrollment path `control.rs:4799-4801` answers a repeat request from the same
key with the stored PEM, so an expired downstream cannot renew with its key;
`add_upstream` refuses re-adding a name in `issued_brokers`/`peers`
(`:4551-4556`).

After 365 days rustls refuses every link, process link and downstream broker;
the site goes dark; recovery is manual deletion of `pki/broker-server.*`,
`links/<id>/*.pem`, and on the upstream removing and re-authorising each
downstream.

Fix: in `Pki::issue` parse the existing cert and re-issue when `not_after <
now + 30 d`; in `enroll` re-sign the stored CSR when the stored cert is near
expiry; a `sys` value with the broker certificate's expiry; a `wyrmd check`
warning.

### D-2 — Low/Medium — rebuild storm from `sys/signing_keys`

`control/signers.rs:175-220`: every 10 s each upstream is polled; any change
writes `Op::SetSigners` and `schedule_reload()` (`:214`), which rebuilds the
whole router runtime (`lib.rs:1478-1510`: quiesce, stop every link, gateway,
engine, storage, reopen). No damping. A buggy or compromised upstream
alternating two valid sets rebuilds the downstream every 10 s forever (an
upstream has `write` below by ADR 0018, not the right to take the site down).

Fix: rate-limit signer-induced reloads (one per 10 min per upstream, keep the
last accepted set otherwise), or apply signer changes without a router rebuild
(they only feed `LimitedKey` lists, not the ACL).

### D-3..8 — Low

- D-3: `lib.rs:1495` `quiesce(180 s)` runs before `broker.stop()`; a revoked
  link/operator/broker keeps its session and the old ACL until the new runtime
  is up; a `config` user with installs in flight stretches it to 180 s. Fix:
  shorten the quiesce when the reload reason is a revocation.
- D-4: `control.rs:4828-4847`: a waiting enrollment for `site` with key A
  refuses later requests for the same name with another key; expiry only when
  the requester stops polling (`:2745-2778`, 600 s). Anyone reaching
  `peers.enroll` (server-auth TLS, no client cert) can squat the real
  downstream's name, and `Reject` would blocklist `broker:<site>` for the real
  one too (`:4815`). Fix: Authorize/Reject act on the request (key), and a
  "drop" that does not blocklist the name.
- D-5: `lib.rs:638-641` sets only `scouting/multicast/enabled`;
  `scouting/gossip/enabled` defaults to `true` (zenoh-config 1.10.1), so
  routers over the QUIC peer links exchange listen locators of every sibling
  site. Autoconnect for routers is empty, so disclosure only. Fix: gossip off,
  plus the `transport/link/protocols` whitelist (known gap 14).
- D-6: `lib.rs:1310` `create_dir_all(&cfg.data_dir)` and `wyrm-state`
  `File::create` use the umask (0755/0644). Protected: `secrets.bin`, `*.key`,
  tokens, `links/<id>/data`. Not protected: registry WAL/snapshots (link params
  incl. hosts, grants, token hashes, CSRs, peer CAs), audit journal, flow
  store, gateway users store (argon2 hashes), history/storage redb files. Fix:
  `data_dir` 0700 (`DirBuilderExt::mode`), WAL files 0600.
- D-7: `control/signers.rs:35-56` `key_set` merges own and learned sites into
  a `BTreeMap` then `.take(MAX_SIGNER_SITES)`; 16 learned names sorting before
  ours drop our own entry, so sites below stop trusting this site's keys. Fix:
  always keep the own entry; cap learned sites only.
- D-8: `lib.rs:1478-1486` `Broker::start(...).await?` in the reload loop: any
  start error (bind, TLS files, engine/storage/scheduler) exits the process
  (`a_listener_port_in_use_ends_the_daemon`). Every ACL-touching action is a
  rebuild trigger; with D-2 an upstream can turn a transient bind failure into
  an outage. Fix: retry transient errors with backoff; document the external
  supervisor requirement.

### Info

- I-D-1: `std::env::remove_var` (`lib.rs:1220`) inside `block_on` on a
  multi-thread runtime; benign now (workers idle), read the variable before
  building the runtime.
- I-D-2: `wyr install/update --param k=v` is the only way to pass driver
  params, so connection passwords land in shell history and `ps`; only
  `set-secret` reads stdin. `load_key` (`main.rs:595-601`) does not warn on a
  world-readable key file and does not zeroize the hex text. Same for
  `wyrm-mcp` (AI-2).
- I-D-3: an upstream with `allow_config` can add a *third* upstream with
  `allow_config` on the downstream (`acl.rs:466-472`): root trust is
  transitive; consistent with the owner decision, worth stating in ADR 0018.

### Checked and sound

One root CA on every listener with `enable_mtls`, stale `peer-trust.pem`
removed, `#enable_mtls=false` only on the enroll endpoint, per-endpoint
CA/cert/key for upstream connects, `verify_name_on_connect` never disabled,
endpoint-parameter injection (`#?;`) refused, `plaintext_off_loopback` fails
closed on unparsable hosts, `rest` only in `dev` + loopback, multicast
scouting off, adminspace read-only behind the ACL; subjects `cn-<id>`/operators
bound to `tls`, brokers/upstreams to `quic`, link ids cannot contain `:`;
enrollment as in §3; signer propagation shape-validated, `config` keys only
through `config_from` at every hop, never admin keys, never `write` on `sys`,
poll failure keeps the last set; embedded links and the admin attach before
`runtime.start()`, so no window with a permissive ACL; process links
`env_clear` + whitelist, token file 0600, parent-pid watchdog, output ring
4 KiB / 1 MiB; FFI every entry under `catch_unwind`, null/UTF-8 checks,
alloc/free pairs match, `wyrm_open` refuses `tls/` and off-loopback plaintext;
`wyrmd` `#![forbid(unsafe_code)]`, `deny_unknown_fields`, `state_anchor_dir`
outside `data_dir`, reserved ids, passwords from stdin only; `wyr keygen`
0600 `create_new`, approval tokens ≤900 s, exact key, human subject only.

## 9. AI surface (`tools/wyrm-mcp`, `links/agent`)

### AI-1 — High — MCP approval binds the key, not the payload

An approval is a `ptok` a human mints for exactly `<node>/~set` or
`<node>/~act/<a>` (`tools/wyrm-mcp/src/check.rs:189-233` checks `g.k == key`).
`do_action_invoke` (`server.rs:528-583`) builds `args` from whatever the MCP
client sends on the second call and sends them with the human's token
(`:573-575`); the dry run only *shows* `would_send`. A prompt-injected MCP
client shows a benign dry run for `sys/links/~act/install_url {url: good}`,
the operator mints the token, the client sends `dry_run=false` with `url:
evil`. The same for `update_permissions`, `set_secret`, `enroll`, peers, any
config `~set`. The token is single-use and ≤15 min, which is enough for one
action. The agent link does this right: the plan payload is stored at
`propose`, approved by hash/state compare-and-set, and executed from the stored
plan (`links/agent/src/lib.rs:1419-1437, 1181-1197, 1468-1475`).

Fix: bind the approval to the payload: a claim `h = sha256(canonical CBOR of
{key, payload})` (spec 04 addition, `wyr token --args-hash`), the MCP server
refuses to send when the hash differs, the SDK verifies `h` when present.

### AI-2 — Medium — MCP key is a full admin key

`main.rs:28-31, 81, 245-255`; `server.rs:214-219` caps tokens at `write` but
the verifier (`auth.rs:120-131`) trusts any admin-key signature at `config`;
only the claims' own `max` lowers it. Whoever reads `ai.key` (in `.mcp.json`
env, no mode check in `load_key`) is a full administrator of every site key.
`docs/mcp.md` lists this under "Not yet". Fix: issue an MCP identity like agent
keys (`LimitedKey {cap: Write, scopes, subject: Some("ai:<name>")}`), refuse
`o+r` key files.

### AI-3 — Medium — `api_base` exfiltrates the API key

`links/agent/src/llm.rs:51-72` accepts any `https://host[:port]`; the key goes
in `x-api-key` (`:127-131`). `api_base` is an ordinary param; `update`
schedules a reload. A `config` operator on `sys/links/<agent>` with no access
to `secrets.bin` points it at a host with any publicly valid certificate and
receives the key. Fix: make `api_base` a `dest` of the secret (ADR 0004: a
change drops `anthropic_api_key` until re-entered) or a `wyrmd.json5`
allowlist; audit the change.

### AI-4 — Medium — autonomous plans under `require_approval: config|never`

`tools.rs:52-56`, `lib.rs:1444-1466`: with those modes every `write`-level
step the model proposes under `allowed_prefixes` runs with the agent's token;
`ask` is `write`-level (`lib.rs:874-882`). Everything fed to the model (`~meta`
names/descriptions/enum names/attrs, `~val` strings, `pub/**` profile attrs,
flow `~def`s, tool error text) is unframed, so a device or a `write` user puts
instructions in a description or value. The default `write` mode keeps a human
in the loop, but the model's `reason` and `model:` log lines shown to the
approver are attacker-influenced. Fix: document the modes as "autonomous
writes from untrusted tree text", delimit tool results as data, show
`plan[].args` verbatim to the approver (also for the future Flutter UI).

### AI-5..8 — Low

- AI-5: admin `LimitedKey` scopes take `allowed_prefixes` verbatim
  (`control.rs:907-918`) while the agent expands site-relative entries
  (`lib.rs:757-770`): `["downstream/mock"]` fails closed with `NoGrant`;
  `["wy/<site>"]` makes the key valid at `write` on every link. Normalise with
  one function; refuse prefixes above `downstream`.
- AI-6: MCP output count-capped (`LIST_LIMIT_MAX` 1000, `STREAM_MAX` 1000), not
  byte-capped; a device-controlled link pushes multi-MB results to the LLM
  client. Cap bytes (~256 KiB) and mark `truncated`.
- AI-7: `Budget::roll` resets on any day change, including backwards
  (`lib.rs:402-420`); a response with no `usage` (AI-3) is not charged. Roll
  forward only; charge the estimate when `usage` is missing.
- AI-8: `jti` cache in memory (known T9); MCP pre-check does not verify
  signatures (advisory only).
- I-AI-1: `tree_resolve` `match` concatenated raw into the selector
  (`wyrm-client/src/lib.rs:456-460`); read-only effect; escape `&`.
- I-AI-2: `.claude/skills/*` and `docs/superpowers/**` run only repo-local
  cargo commands; no Flutter approval UI exists yet.

### Checked and sound

MCP: stdio by default, `--http` loopback only, bearer ≥32 chars constant-time,
`Host` allowlist, any `Origin` refused, rmcp debug logs filtered, key in
`Zeroizing`; `dry_run` defaults true; config level and `sys/**` require an
approval; without `--key` no writes; pre-check exact key, same site, not
expired, `perm ≥ need`, no `ai:` subjects; `wyr token` refuses wildcards, `ai:`
subjects, TTL > 900 s; flow deploy proofs exact. Agent: planning tools are
reads only (`flow_validate` only compiles); every read policy-checked; cannot
touch its own subtree; agent key created by the admin as a link secret,
trusted as `LimitedKey {cap: Write}` by links only, not by the engine, storage
or admin; own token denies `sys/**`; approval needs a human with `config`,
tokens pre-checked per plan key and signed for the approver; `may_touch`
re-checked at execution; interrupted tasks never resume; API key `Zeroizing`,
sent only in `x-api-key`, TLS webpki roots with SNI, 8 MiB body, timeouts;
budget check-and-reserve in one lock; task store bounded and HMAC-chained;
`#![forbid(unsafe_code)]` in both crates; no `unwrap` on LLM output.

## 11. Method and limits

Seven focused code reviews (admin/PKI/packages; gateway and clients; SDK, core,
state, storage, history, flow, schedule; protocol connectors; WASM host,
portable links, scheduler, packaging; daemon, peers, CLI, FFI; MCP and agent),
each reading the code in full and reporting only what it verified with
file:line; the cross-cutting findings in this file were re-checked by hand.
Plus `cargo audit` on the lockfile and greps for `unsafe`, disabled TLS
verification and process spawning. Not done: fuzzing, a live run of the
pentest checklist in `threats.md`, review of third-party decoders, the Dart
UI beyond the gateway client, and the e2e suite as evidence (test names were
used only for coverage).
