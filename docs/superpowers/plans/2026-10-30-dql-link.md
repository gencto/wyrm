# DQL link (ADR 0025) Implementation Plan

**Goal:** DSA DQL in WYRM as a portable `App` like the scheduler: standing and ad-hoc queries over
the tree whose tables are nodes, embedded in every `wyrmd` (`wy/<site>/downstream/dql`), as a WASM
package and as a process package, plus `wyr query` in the terminal.

**Architecture:** a pure crate `wyrm-dql` (parser, DSA conversion, CEL bridge, row engine; no I/O,
builds for wasm32) and the link `links/dql` (`wyrm-link-dql`), an `App` that performs the engine's
effects through the `Host`. The portable API gains lists and subtree subscriptions (world
`wyrm:app@0.2.0` beside the frozen 0.1.0).

**Spec:** `docs/adr/0025-dql-link.md` with owner decisions D1–D6 (2026-10-30); rulings of the
build B1–B9 are in that ADR.

## Global constraints

- Code, comments, commits: English. Branch `claude/festive-euler-rc29js`.
- Before a push: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features
  -- -D warnings`, `cargo test` of every crate touched, `cargo build -p wyrm-dql --target
  wasm32-unknown-unknown`, `cargo build -p wyrm-link-dql --features wasm --lib --target
  wasm32-unknown-unknown`.
- Never log values, `ptok` or secrets above `trace`: sink failures log the query id and the status
  name only.
- Constants in one place: `wyrm_dql::engine` (rows, lists, cache, timeout), `wyrm_dql::parse`
  (text, stages), `wyrm_dql::cel` (expression length), `wyrm_link_dql` (queries, budget, sinks in
  flight, publish interval, TTL, table page).

## Tasks

1. **Host API** (done): `ListChange` + CBOR, `Host::list(key, full)`, `App::on_list`, `BufferHost`
   bound `max_lists`, `subscribe` of `<prefix>/**`, reads of other sites under a grant; runtime list
   tasks (full meta, re-list after an overflow, per-key value coalescing); `who_of` capped at the
   effective level; `wit/app2` world 0.2.0, the WASM host linking both versions (test
   `app_versions`), the guest crate on 0.2.0, `links/wasm` delivering `on-list`.
2. **`wyrm-dql`** (done): patterns (Zenoh wildcards over full keys), the pipeline parser with stage
   errors, DSA `filter` → CEL and whole-text conversion, the engine (lists, candidates, sublists,
   value cache, stages, sinks with baseline/throttle/one in flight, bounds, progress, timeout).
   Tests: unit tests per module and `tests/engine.rs` (DSA `>=` and sublist defects, D5).
3. **`links/dql`** (done): tree and actions, store (`index`, `q/<id>`, export `wyrm-dql/1`), ad-hoc
   queries with TTL and sharing, publication at most every `publish_ms`, one timer, a backlog under
   a 700-command budget, 50 sink calls in flight, rights (sinks need effective `config`). Tests on
   `SimHost` (`tests/link.rs`).
4. **Broker, CLI, packages, docs** (done): `wyrm-admin` built-in link `dql` (reserved id, keys,
   trust at `write` on `downstream`, not trusted by itself, overlays), `wyrmd` section
   `dql: {enabled, store_mb}`, spawn with `dql_grants`, process mode `wyrmd link dql`; `wyr query`;
   `examples/packages/build.sh` packs `dql` and `dql-process`; CI builds both for wasm32;
   `docs/dql.md`.
5. **Next** (B9): probe scenario `links/probe/scenarios/dql.json` on the demo, e2e
   `dql_three_modes` (embedded, process, WASM package on one scenario), measurements on deep and
   remote trees (`collect_ms` for depth 2/4/8 × fan-out 10/100, `central → edge → plant`).

## Review focus

1. A wide tree (900 devices) and its removal never exceed the event budget (`tests/link.rs`).
2. A restart with the same values sends no `set` or `invoke` (D5; engine and link tests).
3. A `write` caller cannot create or edit a query into one with sinks; a flow token never passes
   as `config` (B5).
4. A 0.1.0 component (an installed scheduler package) still loads and runs (`app_versions`).
5. Another site is read only under a grant and never written (B4, `buffer.rs` tests).
